# 夜灣 YoruBay 視覺校正：現況審查與分階段計畫

日期：2026-10-01

## 目標

這一輪不是重新設計夜灣，也不是把夜灣改成亮色系。

目標是保留現有資訊架構、Poster-first 探索、手機工具收納、三層 UI 與主 CTA 層級，只校正目前偏黑、偏冷、偏工具感的暗色介面，逐步走向：

> 有燈的夜晚  
> 夜是背景。故事是被燈照亮的地方。工具退到陰影裡。

## 先保留，不應因視覺規格重做的部分

目前已成立、後續 PR 應避免破壞：

- Poster-first 作品探索與輕量作品預覽。
- 手機搜尋／篩選收納與 bottom sheet。
- 故事背景／閱讀／操作的三層方向。
- 桌面故事閱讀寬度限制與可收合工具／狀態區。
- 主要 CTA 與次要操作已有基本層級。
- 作者作品 HTML 與夜灣外殼分離，不應用全站主題強行覆蓋作者內容。
- 現有響應式與手機 story entry 流程。

## 現況審查

### 1. 全站已有暗色基礎，但仍偏黑、偏冷

目前核心值集中在 `base.css` 與 `bao-brand-v2.css`：

- `#090b10` 作為主要夜色背景。
- `#11141b / #171b24 / #1d2230` 作為多層 surface。
- `#f1eee8` 已經是偏暖白，這點應保留。
- 暖金 `#d6aa73` 與 `#e2b66d` 已存在，但目前語義與使用範圍仍不夠清楚。
- 紫色 `#9c8cff` 同時承擔主 CTA、選中、hover、連結等多種角色，後續需減少「什麼都紫」。

結論：不需要另起一套品牌色，只需要把既有顏色重新整理成語義角色，逐步調整比例。

### 2. CSS 已有多層歷史樣式，不能逐頁直接改顏色

目前同時存在：

- `base.css`
- `bao-brand-v2.css`
- `bao-cinematic-home.css`
- `bao-editorial*.css`
- `player-shell-v2.css`
- 多個 chat / story / explore / tool 專用 CSS

另外部分 standalone 頁面仍有大量 inline CSS，例如：

- `account.html`
- `api-guide.html`
- `lm-studio-guide.html`
- `regex-manager.html`
- `about-bao-lab.html`

這些頁面存在不同時期留下的深灰、藍灰、紫紅等色島。

結論：先建立語義 token，再逐區域收斂；不要一次全站搜尋取代 hex。

### 3. 閱讀層方向已存在，但故事頁仍可更明確區分「閱讀」與「工具」

目前故事頁已經有：

- `--story-text`
- `--story-muted`
- `--story-surface`
- `--story-surface-strong`
- 桌面閱讀最大寬度。
- 手機閱讀專用 layout。
- 狀態 rail 與工具 drawer。

但多處仍直接使用 `#0c0f15`、`#11141b`、`#151923`、`#202633` 等硬編碼 surface。

後續應讓：
- 正文閱讀區比背景暖且亮一級。
- 工具列／drawer 再沉下去。
- 背景圖片降亮度與飽和，但作品封面不要被同樣暗化。

### 4. 探索頁目前應「保留結構，只做視覺校正」

PR #158–#160 已完成：
- 手機搜尋／篩選收納。
- 成熟內容與角色分類拆分。
- Poster-first。
- 圖片閃爍修正。
- 輕量作品預覽。

因此後續探索 PR 不應再重做卡片 IA，只處理：
- 降低框線存在感。
- 讓封面保持明亮。
- 卡片資訊退後。
- 主／次文字與背景的舒適度。
- 控制紫色 hover，不讓卡片全部發紫光。

### 5. 工具／設定頁應比故事頁更安靜

API、模型、記憶、MOD、正則、診斷頁應保留工程資訊，但不應搶佔品牌主視覺。

目前像 `regex-manager.html` 仍有明顯紫紅獨立色盤；部分教學頁則已較接近暖灰＋燈火色。

後續統一原則：
- 工具頁使用低裝飾 surface。
- 主要文字清楚。
- 暖金只做引導／focus／重要 CTA。
- 紫色只做品牌與選中。
- 避免每個 panel 都用高對比框線。

## PR 分拆順序

### PR1 — Theme Foundation（本 PR）

只做：
- 建立 `--yoru-*` 語義 token。
- 讓既有 legacy token 指向新語義 token。
- 保持目前實際顏色與布局幾乎不變。
- 紀錄現況與後續邊界。

不做：
- 不改版面。
- 不改卡片尺寸。
- 不改探索 IA。
- 不重新設計故事頁。
- 不大規模替換 standalone 頁面顏色。

### PR2 — Reading Comfort

範圍：
- 故事背景、閱讀面、字色、行高、段距、閱讀寬度。
- 背景圖片暗化／模糊與正文遮罩。
- 工具、usage、composer 降低視覺存在感。
- 手機長時間閱讀檢查。

### PR3 — Explore / Poster-first Polish

範圍：
- 首頁／探索／作品預覽。
- 減少硬框。
- 保護封面亮度。
- 暖金只出現在「繼續故事／當前故事」等燈火語義。
- 不重新設計 #158–#160 的搜尋與預覽流程。

### PR4 — Shared Cards & Controls

範圍：
- 共用按鈕、focus、hover、card、border、radius、shadow。
- 控制紫色使用頻率。
- 正式定義 lantern CTA 與一般 primary CTA 的使用邊界。

### PR5 — Creator / Workbench

範圍：
- 角色創作、API、模型、記憶、MOD、正則等工具頁。
- 降低裝飾，強化資訊清楚與長時間設定舒適度。
- 收斂 standalone inline CSS 色島。

### PR6 — Responsive Polish

範圍：
- 手機／PC 逐頁對照。
- 中央閱讀寬度。
- 側欄、狀態欄、bottom nav、safe area。
- 不在這一輪增加新功能。

### PR7 — Final Visual QA

逐頁檢查：
1. 第一眼是角色／故事，還是工具？
2. 黑色是否過重？
3. 灰色是否過冷？
4. 紫色是否過量？
5. 正文是否比工具區舒服？
6. 封面是否被遮罩吃掉？
7. 是否有過多邊框與巢狀卡片？
8. 是否同時存在太多高亮 CTA？
9. 暖金是否只用在真正具有「燈火」語義的位置？
10. 手機連續閱讀是否安靜？

## PR1 驗收標準

本 PR 合併後，網站視覺應該「幾乎還是原本的網站」。

這是刻意的。

PR1 的目的不是立即換皮，而是讓後續所有視覺調整有同一套語義控制點，避免：
- 每頁各寫一組 hex。
- 同一種 surface 有十幾種近似色。
- 暖金變成另一個到處出現的主品牌色。
- 為了改視覺破壞既有 UX。
