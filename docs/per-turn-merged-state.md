# 每輪正文與狀態合併更新

共用主模型的狀態追蹤沿用 `BAO_STATE_V1`，每輪故事請求都要求正文後附一個狀態 JSON；沒有可確認變化時輸出 `{}`。舊存檔的 `cost.stateInterval` 不再延遲此路徑，仍保留原值供獨立狀態模型使用。不啟用狀態追蹤的作品不受影響。

## 資料流

1. 沿用既有上下文與 Stable Prefix；狀態契約追加於最後的玩家訊息。
2. 一次主模型請求產生正文與增量。串流隱藏完整或尚未完成的機器標記。
3. 收到完整結尾後，解析單一 JSON 物件，再由 `BAOHelperData.stateUpdate` 驗證允許的模組、人物欄位、數值及時間資料。
4. 使用既有 `GameState.applyUpdate`、動作版本協調、UI 重繪和故事存檔，不另建狀態副本。
5. 記憶整理沿用原有調度；不增加收藏分析模型或自動修復請求。

獨立狀態模型仍走原有分流與整理間隔，玩家的連線選擇不變。此變更不新增回憶收藏頁、解鎖條件或秘密資料輸出。

## 失敗與成本

缺少附錄、JSON 格式錯誤或截斷時保留正文，將本輪保留於既有待整理佇列，下一輪合併請求最多補四輪舊資料，不靜默補發第二次狀態 API。完整回應中的陣列根節點、尾隨雜訊不會被擷取成可套用的 JSON。物件模組採欄位增量；集合仍沿用既有整體取代語意，契約要求保留既有項目。

每輪檢查會增加輸入契約和狀態輸出 Token，不承諾總費用下降；回應上限不足仍可能截斷附錄。Stable Prefix 的內容與位置不變，但供應商實際快取命中率需用真實流量觀察。測試使用假模型，不代表所有模型都會遵守格式。

## 驗證

核心回歸涵蓋舊間隔 2／20 的首輪更新、空增量、串流隱藏、缺失與無效附錄、待補資料、獨立連線保留、修仙模組、狀態快照、分支重算、記憶任務隔離與使用量統計。瀏覽器測試 `per-turn-merged-state.spec.cjs` 使用假 LM Studio 回應，在 390／1440 寬度透過實際發送流程檢查每輪請求數、UI、歷史與存檔還原。
