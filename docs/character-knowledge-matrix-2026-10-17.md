# 事件知情紀錄（角色知情表）｜2026-10-17

## 實作範圍

沿用既有 `episodicMemory.events[]`，**沒有新增第二套世界事件索引或額外的每輪 API 呼叫**。

- 事件抽取時的 `knowledge[]` 保留目擊、被告知、傳聞、推斷與來源 message ID。
- 後續智慧摘要可回傳 `knowledgeUpdates[]`：只引用已存在的 `eventId`，附上此次原文的來源 message ID；前端驗證這些來源是否屬於此次整理區間，以及是否晚於同區間原事件。拒絕不存在的事件、偽造來源與相同時間的非後續更新。
- 新增知情以歷史版本追加；故事回到更新前的分支時，召回仍以該分支實際存在且未修改的原始訊息為準，回退到先前有效的認知。
- `recall()` 對同一角色優先採用**最近具有效來源**的認知。多人共用一次生成請求時，只有所有說話者都有來源且認知內容相同，才會召回私密記憶；未確定說話角色就只召回公開資訊。
- Canon `knowledge` 記事本保留在玩家管理頁，但不再無條件放入 Core/Relevant Prompt，避免一張全域知情筆記直接提供其他 NPC 的秘密。
- 記憶工作台的 Canon 區新增預設折疊的**角色知情一覽**，可檢查最近 20 件具有有效原始訊息證據的事件和各 NPC 當前認知，未列出表示沒有可核對知情證據（不是證明其永久不可能知道）。

## 資料與成本

- 保存於現有單故事 `GameState.current.episodicMemory`，隨 IndexedDB 故事存檔、匯出及分支一起走；不使用雲端帳號或跨故事索引。
- `knowledgeUpdates` 與現有智慧摘要同一次模型呼叫生成；前端回憶檢索及知情表渲染沒有 API 呼叫；模型回應可能增加少量 Token。
- 記憶召回只加在最新玩家訊息前的動態區域，不變動固定 System Prefix。
- 玩家關閉 `episodicRecall` 或啟用完整原文模式，仍維持現行事件召回開關行為。

## 已知界線

本功能是**有來源的角色知情檢索門檻**，並非保證單一 LLM 回合能完全隔離資訊。既有原始對話、舊長期摘要、手動筆記、其他世界書或角色卡，仍可能含有 NPC 不該知道的資訊；如果要做到真正的不同角色隔離，需要對所有提示資料源做 actor-scoped 編排，或使用分角色生成流程。

`public` 表示事件被標記為公開，並不代表每位 NPC 在劇情設定裡必然聽聞。模型提取有幻覺風險，來源 ID 檢查只能證明「引用了原文」，不是證明陳述必然真實；編輯、匯入或重建事件後，請以角色與時間線測試驗證。
