# 故事討論與匯入設定拆分

## 玩家入口

- 故事控制中心 → 故事討論。使用目前故事模型，參考長期摘要及最近 12 則可見正文訊息；討論僅保留最近 24 則，可另存 TXT。
- 故事管理 → 匯入外部紀錄 → 確認說話者 → 確認身分並拆分設定。Context Pack 草稿編輯頁亦可重新開啟拆分。
- 拆分使用既有記憶整理模型與分批預算，每次最多 8 批；成功批次保存進度。完成全部來源後才開放修改與勾選確認。
- 四類確認結果只新增至目前故事：AI 人物（additional）、玩家 extra、私人世界書、長期前情筆記。同名人物拒絕覆蓋，原作品與原對話不更動。這不是公開上架或獨立角色卡產生器。

## 資料與請求邊界

`state.storyDiscussion` 保存獨立討論；`state.settingSplitJob` 保存來源指紋、路由計畫、整理游標、草稿與套用標記。兩者均隨既有完整故事備份保存；TXT 正文匯出不包含討論，討論有自己的 TXT 入口。舊存檔不需要遷移。原始外部紀錄仍由現有 Context Pack 草稿來源機制管理。

討論只組合白名單中的正文與摘要，不呼叫 buildSystemPrompt 或加入 Chat.messages。請求標記為 __storyTool / __discussionTask，經既有 API、使用量與燈火結算；修訂 wrapper 明確跳過它。討論不自動寫入記憶；玩家選擇「編輯並存為長期筆記」後才加入 state.memory。

拆分走 BAOMemoryCore.foldText / taskSystem，保留 schema 與完整輸出驗證。來源、路由改變不沿用舊進度。未完成、截斷或被阻擋的結果不可套用。所有新增操作先產生純資料副本，再一次套用；一份草稿的 applied 標記防止重試保存重複新增。持久化失敗時保留頁面及資料，明示重試，不宣稱已保存。

工作使用每故事維護鎖，保留未送出的正文輸入；關閉面板 abort 請求，過期結果不寫入其他故事。討論和拆分草稿不進入正文修訂快照，內部重生成／版本切換保留當前工具資料；外部歷史分支及回溯仍遵守原檢查點語意。
