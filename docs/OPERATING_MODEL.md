# YoruBay / BAO-LAB 營運模式

> 決策日期：2026-09-28  
> 狀態：目前產品與營運基準

## 核心原則

YoruBay / BAO-LAB 採 **Local-first + BYOK + 免費核心 + 自願支持**。

- 工具免費。
- 公開作品免費遊玩。
- 玩家自己的作品免費遊玩。
- BYOK 免費，模型費由玩家直接負擔。
- 本機故事、記憶、狀態、世界模組、故事庫、創作工具等核心能力不設付費牆。
- 不為了營利刻意拆掉既有核心功能再付費解鎖。
- 玩家願意支持平台時，可自願「投餵肉包」。
- 玩家喜歡作者作品時，應優先直接支持作者。

## BYOK 與後端邊界

普通 BYOK 對話原則上：

```text
玩家瀏覽器
→ 玩家自己的 API Key
→ AI Provider
```

不應只為了平台計費或會員驗證，把所有 BYOK 聊天強制代理到 YoruBay Worker / D1。

夜灣後端主要服務：

- YoruBay 帳號與身份
- Hosted AI 官方額度
- 餘額與 usage
- 確實需要線上服務的未來功能
- 必要的特殊地區 / Provider relay

若 Provider 可由瀏覽器安全、正常直連，優先 Direct；Relay only when necessary。

## 帳號定位

帳號不是使用核心故事功能的必要條件。

沒有帳號的玩家仍可：

- 瀏覽與遊玩作品
- 使用自己的 API
- 將故事保存在本機
- 使用本機記憶、狀態與世界功能

帳號主要是 YoruBay 線上服務的身份層，不應演變成核心功能的強制入口。

## 官方 AI 額度

官方 AI 額度是便利服務，不是會員費。

玩家可自由選擇：

- 免費使用平台 + 自己 BYOK
- 免費使用平台 + 另外購買 YoruBay Hosted AI 額度

官方額度價格需至少涵蓋：

- 上游模型成本
- 金流成本
- 匯差與海外刷卡費
- VAT / 稅務
- 上游儲值費用
- Worker / Relay 等必要成本
- 合理風險緩衝

官方額度的第一目標是避免平台倒貼，不以 Token 差價作為主要獲利中心。

## 平台支持

平台主要以自願支持維持：

```text
玩家喜歡夜灣
→ 投餵肉包
→ 網域 / Hosting / Worker / D1 / Relay / 測試 API / 開發維護
```

不強制訂閱、不以核心功能 Premium 化作為目前主要模式。

原則是：

> 能被支持到足以維持，就繼續營運；若長期無法負擔必要成本，則縮減高成本服務，必要時停止營運。

## 作者生態

創作本身免費。

作者可免費：

- 使用角色卡創作工具
- 匯入 PNG / JSON
- 製作與測試作品
- 自己遊玩自己的作品
- 使用本機創作與世界工具

### 公開上架

目前規劃：**NT$300 / 作品**，定位為一次性「作品審核與公開部署服務費」。

此費用不是：

- 角色卡購買費
- 會員費
- 創作工具費
- 玩家斗內抽成

基本上架可包含格式檢查、metadata、封面與作者資料、部署、基本測試與首次部署錯誤修正。

重寫角色、Prompt Engineering、Regex、HTML/CSS、專用 UI、世界模組、圖像製作與長期代維護屬額外客製服務。

### 作者支持

玩家對作者的支持原則上：

```text
玩家
→ 作者自己的合法付款渠道
→ 作者
```

YoruBay 不以抽作者斗內作為主要收入來源。

平台開發者本身也是作者；玩家可以分別因「平台」或「官方作品」選擇支持。

## 目前不採用

- 強制月費才能玩
- 公開作品付費牆
- BYOK 抽成
- 記憶 / 狀態 / 世界模組等核心功能付費解鎖
- 創作工具訂閱制
- 作者斗內抽成
- 每回合聊天抽平台費

## 收入來源

目前規劃的收入來源：

1. 玩家自願支持平台
2. Hosted AI 官方額度服務
3. 作者公開上架服務
4. 作者 / 作品客製服務
5. 開發者作為作者收到的作品支持

## 開發決策檢查

新增商業功能前，先問：

1. 這是玩家本機即可完成的核心能力嗎？若是，優先保持免費。
2. 這會不會讓普通 BYOK 對話不必要地經過後端？若會，應重新設計。
3. 夜灣是否為此持續支付真實資源或人工？若是，才合理考慮收費。
4. 是否會提高作者創作門檻或對作者斗內重複抽成？若是，原則上避免。
5. 是否破壞 Local-first、BYOK、模型自由？若是，不應作為預設方向。
