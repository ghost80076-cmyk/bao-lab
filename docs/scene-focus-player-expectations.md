# 場景投入保護與玩家劇情期待（可選敘事偏好）

## 目的與來源

吸收社群玩家《角色扮演底層協定 v4.10.11》兩個設計：深入互動期間避免無端打斷，以及將玩家場外希望探索的方向與玩家角色實際意圖分開。這裡只增加夜灣既有「今晚的故事」兩個可選設定，不引入玩家協定的整套回合計數／狀態表／全知導演本。

## 玩家入口

- **場景投入保護**：在「今晚的故事 → 故事方向」選擇「場景專注 · 不無故打斷」。預設「依作品安排」；這不是全域硬規則，也不會停掉世界時鐘、NPC 離場、已成立期限、危險或合理後果。場景是否正在連續互動由現有正文模型依上下文判斷；沒有新增追蹤器、偵測器或模型呼叫，不能保證模型每次都正確判讀。
- **玩家的劇情期待**：選填，最多 240 個字元。描述場外希望故事有機會朝哪個方向探索，例如希望關係出現修復契機但不保證和好。不是角色內心、已發生事件、NPC 可讀的消息、導演的強制結果或新的承諾／同意。
- 建立故事前改動偏好只作新故事起始設定；進入故事後調整只保存目前故事。舊故事沒設定時維持原行為；不操作、取消、恢復預設後取消、未變更套用不新增存檔及系統訊息。
- 設定欄不擅自掃描聊天推測「玩家期待」；只有玩家主動填寫才生效。一般的故事輸入與角色對話不能被視為此欄位的永久授權。

## 技術接法

沿用 `config.narrative` 的 `sceneFocus: "card" | "protect"` 與 `storyExpectation: string`，由 `normalizePrefs` 正規化；後者移除控制字元、去頭尾空白且最多 240 字元。原本 `BAONarrativeSettings.buildPrompt` 只在非預設時產生指令，並由 `App.buildSystemPrompt` 寫入既有的 Stable Prompt；`prompt-cache.js` 的穩定／記憶／動態分段及 `prompt-orchestrator.js` 不改動。不得額外重新建快取或新增 API 呼叫。

當玩家修改有效的故事方向時，新的 Stable Prefix 與原本不一樣，下次可能需要供應商重新暖機。設定不變時輸出 bytes 固定。劇情期待是戲外資料，不應被洩露成 NPC 的認知；但與所有放入同一次主模型請求的背景資料一樣，提示詞約束不是模型內部絕對的資訊硬隔離，不要宣稱零洩漏。

## 驗收

- `tests/narrative-settings-core.cjs`：預設為空、上下限、無效設定、故事期待清理、場景保護規則與摘要顯示。
- `tests/narrative-prompt-pipeline-core.cjs`：請求完整組裝；固定前綴只出現一次、最後一輪動態輸入不混入期待、未變更請求逐字一致。
- `tests/e2e/narrative-cache-preservation.spec.cjs`：390／1440px 的視窗操作；取消不寫入、套用只改故事設定、無模型呼叫、不改全域偏好或故事 session、原樣重開／保存零變動、清除後回復原 Prompt。
- CI 使用現有 Core tests 與 story-experience Browser E2E；本 PR 不將合成測試視為不同提供者真實 LLM 的敘事遵循率，也不宣稱已量測快取命中／Tokens 節省。

## 後續刻意不納入

- 觀賞模式與玩家角色控制權交接；另立 PR 驗證，不擴張本次的 `playerPortrayal` 權限。
- AI 導演或 NPC 背後自動計畫的修改；已存在的 AI 導演實驗可日後選擇讀取玩家明確期待，但本批不動實驗與生產流程。
- 從玩家無聲互動自動推論期待、場景 AI 情緒辨識、每輪強制事件密度／關係升階、定時後台世界推演。
