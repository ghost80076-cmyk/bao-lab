# YoruBay Experience 3.0｜第一批：操作與視覺基礎

日期：2026-10-15。依既有夜灣產品、競品比較、手機玩家回報建立。這不是新的故事引擎，也不是重做 Play／Studio。

## 核心問題

- 既有聊天側欄已有五組功能，仍以開發模組邏輯分類。手機開「全部功能」容易看到密集按鈕。
- 玩家已經需要理解 API 與連線；進入故事後不應再次面對整個設定後台。
- 目前語義色票已建立（PR #170、#349），但預設仍只充分服務暗色，日間與暖色氛圍缺乏完整選擇。
- PR #121／#131／#132／#189／#611 已有搜尋、故事總覽、世界書階層、手機密度優化；必須重用功能，而不是複製入口。

## 本 PR（第一批）做了什麼

1. 使用者本機偏好：輕鬆／標準／專業，夜港／晨霧／暮玫。第一次進入使用「輕鬆＋夜港」。
2. 同一組工具，改依玩家任務分組：「此刻與顯示」「故事與存檔」「人物與世界」「故事體驗與 AI」「其他與支援」。
3. 工具層級**只控制預設展開哪些分類**，所有模式都保留完整功能，不修改帳號權限、故事能力與 API。
4. 共享外觀設定 dialog；頂部 icon 按鈕和工具抽屜都能開啟同一視窗。偏好存在 localStorage，沒有伺服器寫入或故事備份格式變更。
5. 以既有 --yoru-* 色彩變數建立兩種新色盤，對系統 UI 做受控覆蓋，不套到作者自訂 HTML 上。

## 仍待改善的介面（後續 PR）

- **首要：** 真正完成三主題的全站視覺稽核，確認探索卡片、帳號、Builder、世界書、作者工作台的硬編碼色彩沒有降低對比或留下色島。尤其深色遺留的固定白字與主題切換時的背景。
- 手機輸入框及鍵盤彈出時的縮放／捲動、底部抽屜關閉與開啟一致性。
- 聊天訊息仍維持環境描寫、動作、人物對話自然交錯；UI 不強迫把小說文字拆成對話卡。
- 世界書瀏覽和召回說明、人物／關係視覺化、作品專屬主題，須有資料來源與玩家可知性邊界。
- 連線方式只展示玩家需要的層級；深度技術參數在專業模式更容易發現，但不打斷一般玩家流程。
- 不應在這一批加入第三套 Play／Studio 或全新資料副本。

## 驗收準則

- 手機 375／390px、桌機 1280／1440px、一般窄視窗：無橫向溢出，抽屜和 dialog 能關閉、主題能切換。
- 三層工具都能操作相同的原始功能；沒有任何工具因「輕鬆」被永久隱藏或停用。
- 主題及操作偏好可在同裝置重新整理後保留；切換不修改故事資料、Persona、模型路由、Memory／Cache、Regex／MOD。
- 保持既有作者定義的 Gameplay Theme、封面、富文字輸出與 CSS 隔離。
- 跑 Core tests、Fast Browser E2E 與手機 regression 後，才評估下一批與是否合併。

## 設計定位

預設是精緻沉浸式故事平台，進階才展開創作工具與診斷能力。視覺的柔和不意味功能減少；複雜功能可以被找到，但不必預設全部呈現。
