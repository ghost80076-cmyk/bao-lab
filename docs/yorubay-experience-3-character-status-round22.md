# YoruBay Experience 3.0｜第二十二輪：人物狀態閱讀層級

日期：2026-10-15。

## 問題
人物狀態頁原本同時承擔閱讀、Context 指定、NPC 名冊入口與狀態欄管理。人物一多時，每張卡把所有欄位一次攤開；整張卡又同時是「下一輪重點」按鈕，頂部還並排多個管理入口，玩家容易把「目前在場」「下一輪參考」「狀態欄設定」視為同一件事。

## 本輪目標
把人物頁重新整理成：

**人物總覽 → 本場人物 → 關係／狀態 → 下一輪參考 → 需要時才進管理**

不新增資料結構，不改世界狀態、不改 Prompt 規則。

## 實作
- 頂部新增「人物與狀態」摘要：人物數、本場數、下一輪參考數。
- 保留「人物名冊／本場」作為常用入口，因為它直接回答誰在場；「狀態欄管理」移入原生 details「管理人物與狀態」。
- 每張人物卡先顯示前四個目前可見欄位；第五項以後收進「查看另外 N 項狀態」。
- 關係、好感、信任、羈絆、親密類欄位只做視覺區分，不重新排序，也不改玩家已設定的欄位順序。
- 本場 NPC 顯示「本場」badge；這個 badge 只來自既有 `sceneNPCs()`。
- 「下一輪重點」文案改為「下一輪參考」，並提供獨立按鈕；卡片空白區仍保留原本的快速點選能力。
- 點擊欄位收合、管理 details 或人物名冊入口不會觸發下一輪參考切換。
- 晨霧／暮玫／夜港都使用既有 `--yoru-*` 語義色票；手機管理選單固定在底部導覽上方，避免操作被遮擋。

## 資料邊界
- `selectedContextCharacters()` 與 `toggleContextCharacter()` 完全沿用原實作。
- 「本場」仍由 NPC presence/location 決定；下一輪參考不會改 NPC presence。
- 收合只是 DOM 顯示層，不刪除、不改寫任何狀態欄值。
- 欄位順序仍使用目前 `visibleFields(config)` 的結果，沒有為 UI 額外重排。
- 狀態欄管理、人物名冊、記憶、Prompt、世界書、模型、快取與計費資料結構不變。

## 驗證
沿用 `portable-story-actors.spec.cjs` 加入 390 / 1280px：
- 摘要數字、人物卡、本場 badge。
- 前四個欄位直接顯示、其餘兩項預設收合後可展開。
- 關係類欄位有視覺分類但值不變。
- 下一輪參考切換只更新 Context selection，不修改 NPC state。
- 管理工具預設收起，需要時展開。
- 人物名冊入口仍可直接開啟。
- 晨霧／暮玫人物卡配色會跟隨主題。
- 無橫向溢出。
