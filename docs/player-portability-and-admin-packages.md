# 玩家資料下載與管理頁作品包上架

## 玩家入口

- 人物庫 →「匯入／匯出人物」：完整人物庫 JSON 備份、TXT 閱讀版、JSON 匯入。
- 每位人物 →「更多」：只下載該人物的 JSON 或 TXT。
- 人物 JSON 使用 `yorubay-person-library` v1，區分 `players` 與 `actors`。手動匯入新增副本，不覆蓋現有人物；每類最多 100 位，超量拒絕，不截斷。兩個人物庫鍵值寫入失敗會回復原值。
- 故事存檔工具 →「下載本章對話 TXT」：目前分支的玩家／故事訊息原文，不含 system 訊息、context_content 或 API 設定。TXT 用於閱讀；要還原狀態、章節及分支，請使用原本的完整故事 JSON。
- 裝置搬家包增加獨立人物庫；舊包沒有 `people` 時仍可匯入。同 ID 人物在搬家時更新。寫入前驗證所有故事與人物數量；搬家各資料庫仍依序寫入，若後段儲存失敗會顯示已完成數量，並保留原備份檔供重試，不宣稱整包具跨資料庫交易。

## 管理頁作品上架

`admin-wallet.html` 接受原生夜灣 ZIP、PNG、JSON。ZIP 以共用作品包核心解壓與組裝，世界書分檔還原進角色快照，Regex 以 `import_metadata.work_package_regex` 發布。

- 發布預覽顯示圖片數、封面與待適配項目。原始來源與未被使用的其他附件保留在原 ZIP，不會公開到 repo。
- 公開上架目前最多 32 張圖片、合計 12 MiB；每張最多 10 MiB。超限拒絕，不移除圖片。這是管理頁上架界線，玩家本機作品 ZIP 原上限不變。
- Worker 驗證圖片 ID、重複、base64、MIME／檔案簽名、宣告與實際圖片一一對應。
- 圖片以帶發布時間的獨立路徑寫入同一 PR，保留舊版本圖片。角色內的本機圖片引用轉成正式靜態資產 URL，圖片清單保留原 path、when、role 及新的 public_url。
- 公開作品場景、立繪與圖庫使用正式靜態路徑。Regex 的隔離框僅讀取受驗證的本站素材路徑，再產生顯示用 data URL；不新增腳本或 same-origin 沙盒權限，不改寫玩家儲存的 Regex。
- 原本的作者權利確認、管理員驗證、先建立 PR 後部署流程維持。

## 驗證

新增人物與對話匯出／還原、過長欄位拒絕、搬家人物資料、圖片缺漏／偽造／重複拒絕與 PR 圖片傳輸檢查。瀏覽器涵蓋 390／1280px 人物下載與重載、管理頁 ZIP 發布 payload，以及正式靜態圖片在 opaque sandbox 的實際解碼。
