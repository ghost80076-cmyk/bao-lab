# 本機手機機關：密碼、已讀與跨 App 解鎖

主站手機的第二階段，在 `phone_ui.interactions` 定義可選的作者機關。讀取筆記、照片或聊天室，以及輸入故事密碼，會在本機更新目前故事的 `phoneInteractions`；不傳送聊天、不呼叫模型，也不修改作者原始作品。

## 可直接套用的手機資料

創作室勾選「這張作品使用手機介面」，可先用一般表單建立聯絡人、聊天室、X 貼文、相簿、備忘錄及讀取機關；下方 JSON 僅供舊卡搬運或進階編輯。既有故事也能由「手機設定 → 更多設定與匯入資料」套用同樣格式，覆寫只作用於目前故事。

```json
{
  "userName": "玩家",
  "apps": ["notes", "kakao"],
  "contacts": [{"id":"friend","name":"好友"}],
  "notes": [
    {"id":"clue","title":"桌上的便條","text":"舊房間的號碼：0427。"},
    {"id":"safe","title":"加密筆記","text":"原來那個聊天室還在。"}
  ],
  "threads": [{"id":"hidden-chat","name":"舊聊天室","participants":["friend"],"messages":[{"from":"them","senderId":"friend","text":"你找到那張便條了嗎？"}]}],
  "interactions": {
    "version": 1,
    "locks": [
      {"target":{"app":"notes","id":"safe"},"code":"0427","hint":"四位數的房間號碼"},
      {"target":{"app":"kakao","id":"hidden-chat"},"hidden":true}
    ],
    "events": [
      {
        "id":"reveal-chat",
        "when":{"action":"unlock","target":{"app":"notes","id":"safe"}},
        "requires":[{"action":"read","target":{"app":"notes","id":"clue"}}],
        "unlock":[{"app":"kakao","id":"hidden-chat"}],
        "notification":"舊聊天室已解鎖。"
      }
    ]
  }
}
```

先讀便條，再輸入 `0427` 開啟筆記，就能在 KakaoTalk 看到舊聊天室。若先猜中密碼、之後才讀便條，條件補齊時仍會解鎖。照片的目標以 `app:photos` 搭配該張照片的 id 指定；與筆記、聊天室可互相連動。

## 欄位與規則

| 欄位 | 規則 |
| --- | --- |
| version | 固定 1；未提供 interactions 或設 null 沿用舊手機玩法 |
| locks | 最多 80 個，target 不得重複 |
| target | `{app,id}`，app 可以是 notes、photos、kakao、x；內容 id 必須存在；X 貼文需要穩定 ID 才能引用 |
| code | 選填，最多 128 字的**字串**；區分大小寫、不自動去空白，保留開頭的 0 |
| hidden | true 時解鎖前不顯示；這種目標只能由事件解鎖 |
| hint | 最多 300 字；只顯示給可見的鎖定項目 |
| events | 最多 40 個，事件 id 必須唯一 |
| when | `{action,target}`，action 為 read 或 unlock |
| requires | 最多 12 個額外條件，需全部成立；可跨 App |
| unlock | 最多 12 個目標，均需預先設定對應的 lock |
| notification | 最多 300 字，本機通知，可關閉；不代 NPC 送出新對話 |

鎖可只允許線索解鎖（不填 code），或允許密碼與線索任一路徑。事件只會執行一次；解鎖效果可觸發其他 unlock 事件，循環仍會終止。解鎖不等於讀取：事件揭露照片後，需玩家實際打開才會成立 read 條件。無效格式或引用會拒絕作者匯出／玩家設定；異常匯入的機關會保持關閉，避免把失效條件當成已成立。

## 存檔、提示詞與介面

- 已讀、已解鎖與已觸發事件 id 保存於故事狀態，隨儲存、還原、備份和分支快照流動，不共用到其他故事。
- 儲存失敗會還原本次進度；模型回覆中不提交新的機關進度；切換故事後舊介面不能寫入新故事。
- 隱藏項目不出現在清單；鎖定項目不掛載正文、縮圖來源、聊天摘要或傳訊框。
- 密碼、機關規則與鎖定內容不進入系統提示詞。已發生的機關進度放在既有動態覆寫區，固定快取前綴不隨解鎖改變。
- 模型的手機動態區塊及 `modules.phone_ui` 不得覆寫機關規則。一般故事手機動態仍由原本同一輪回覆更新。
- `code` 是本機故事資料，非加密或帳號驗證；原始作品檔可查看。真實 API Key／密碼的既有清除機制保留不變。

## MCP 與範圍

Creator MCP 0.19 同步 `phone_ui.interactions` 的結構與引用驗證，JSON／PNG／ZIP 保留規則。主站與 MCP 使用同一份純機關核心，避免兩邊條件判斷不同。部署順序仍為主站先、MCP 後。

本次提供內容級機關與一次性本機通知，不提供任意腳本、外部網址動作、支付／資源變更、背景模型，或整個 App 圖示的密碼鎖。作者需先把機關引用的內容與 App 配置好。

### 手機近期狀態回饋給主故事 AI

啟用手機時，下一輪主故事提示詞會附上一份有上限的 `【手機近期狀態】`。它不是第二次模型請求，也不會把整支手機重新送出；摘要只取目前故事中已保存、玩家已讀的少量內容，以及玩家自己明確送出的訊息。

- 聊天室最多帶最近 2 個，每個最多 3 則可讀訊息。
- 筆記與照片各最多帶最近 1 份已讀內容；照片只帶標題／說明，不帶圖片資料。
- 已讀的 X／通話只帶最近 1 筆。
- 未讀內容只回報未讀數，不把正文提前交給模型。
- hidden、locked 與機關尚未解鎖的正文會先經既有 `forPrompt` 資訊邊界過濾，不會藉由摘要外洩。任何曾被作者設為機關鎖定目標的正文，即使之後解鎖，也維持 local-only，不放進 provider body；模型最多知道已解鎖後可見的標題／ID。
- 摘要整體有固定字數上限；用途是維持「上一輪手機發生了什麼」的連續性，不是要求模型重播事件。

即使作品沒有設定手機機關，玩家實際打開聊天室、筆記或照片時也會在目前故事記錄 read 狀態，讓後續摘要可以安全帶回已讀內容。這個 read 狀態跟故事存檔、還原與分支一起流動，不修改作者原卡。

### 故事新動態與下一步

手機通知從已接受的主線回覆資料產生，不會另外呼叫模型，也不會把作者的初始內容當成新訊息。通知保存於本故事的 `phoneUI.notifications`，最多 40 筆；同一回覆 ID 不重複產生，玩家自己的訊息不產生收件通知。

鎖定畫面與桌面列出未讀新動態。聊天室與文件使用原始 ID 開啟內容；隱藏項目不顯示通知，鎖定項目只顯示通用提示，解鎖前不清除未讀。已讀更新使用既有故事儲存流程，儲存失敗會還原。切換故事或恢復存檔不共用未讀狀態。

手機空白頁面的「回到故事繼續」只關閉手機並聚焦原輸入框，不填入文字、不送出、不替玩家創造事件。


## X 多角色動態牆與留言串（Phone 延伸）

X 仍是同一個故事內的 Phone App，不是第二套世界模擬，也不會在開啟時自行呼叫模型。作者原始貼文與故事已接受回覆的 Phone 更新會合併顯示。

```json
{"tweets":[
  {"id":"festival-1","authorId":"npc-a","authorName":"社團同學","authorHandle":"@club_a","text":"剛剛校慶發生一件事","date":"週日","eventId":"festival-event-1","sourceKind":"witness"},
  {"id":"festival-reply-1","replyTo":"festival-1","authorId":"npc-b","authorName":"另一位學生","authorHandle":"@school_b","text":"我聽到的版本不一樣","sourceKind":"hearsay"}
]}
```

- 每個 tweets 項目可以是原貼文或留言；留言透過 replyTo 引用父貼文 id，不使用獨立留言資料庫。舊版沒有 ID 的貼文仍可顯示；故事更新缺 ID 時，依已接受訊息產生可重播的 ID。
- authorId、authorName、authorHandle、avatar 為選填。舊版僅有 text/date/likes/replies/reposts 的貼文仍依手機主人顯示；replies 原本的數字統計欄位維持相同語意。
- eventId 僅參照已知故事事件，不新增世界真相或自動改變 NPC 關係。sourceKind 可為 witness／media／hearsay／unknown；它是作者或模型提供的敘述來源標籤，不證明其陳述真實。
- 點進特定貼文才記錄 phoneInteractions.read 中的 x:貼文ID；單純清除 X 通知不算看過貼文。下一輪主故事最多帶入一則已讀貼文摘要，未讀／作者鎖定正文不回傳。
- 玩家回覆走既有 App.sendMessage()；只有主故事回覆產生、且被接受的 Phone 更新才會增添留言，不預先假造 NPC 回覆。模型必須為玩家明確送出的 X 回覆標記 from:me；自己的回覆不產生新貼文通知。
- 既有 interactions.events 可將 X 閱讀設為 when:{action:read,target:{app:x,id:festival-1}}，再解鎖其他 App 線索。密碼、存檔失敗回復、分支與重載沿用原本規則。

本階段不提供背景社群模擬、自動刷新、外部 X API、多人登入或第二次付費模型請求。

### 創作室視覺化建立 X 內容

在角色卡創作室切換「全部欄位」後，啟用手機介面，找到「X｜世界社群」：填發文者名稱、可選的 @帳號、發表時間與貼文正文；若是留言，選擇既有、具有明確 ID 的原貼文。資訊來源和已存在事件 ID 放在選填的進階區。加入後會與其他手機資料保存在同一份 phone_ui JSON，草稿、匯出及匯入仍共用舊路徑。

舊版純文字貼文不會在作者表單中被擅自改寫；沒有明確 ID 的舊貼文暫不能透過視覺化選單被引用作為留言對象。刪除一篇帶 ID 的貼文時，會一併移除它的直接及間接留言，並清理那些貼文所引用的本機閱讀鎖與解鎖事件；其他貼文、聯絡人、筆記及自訂的原始資料不會被該操作改動。X 最多保留 80 筆初始貼文及留言。
