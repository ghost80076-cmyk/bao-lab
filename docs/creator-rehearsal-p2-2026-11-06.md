# 作者角色試演與診斷 P2（2026-11-06）

## 目標

把既有的純文字預覽、BAO Doctor 與本機角色庫串成一條作者可理解的試演路徑，不建立另一套角色資料、故事 Runtime 或模型請求。

## 實作邊界

- 創作室完成頁顯示三步：開場預覽、BAO Doctor、角色試演。
- 「儲存並前往試演」沿用原本的草稿儲存及本機角色庫；先完成持久化驗證，再精準導向 `?work=<角色 ID>&rehearsal=1`。
- 探索頁的深連結可辨識本機角色，不要求它存在於公開 catalog；試演預覽及作品詳情提供返回創作室入口。
- 前兩步不呼叫 AI。第三步只開啟夜灣原本的作品／故事設定流程；作者真正開始故事並送出訊息後，才依既有設定呼叫模型。
- 不修改提示詞組裝、故事狀態、記憶、Context、人物狀態更新、模型路由、Wallet、Worker 或公開上架流程。

## P0／P1 診斷整合

BAO Doctor 延伸靜態檢查，但不把相容資料誤判為錯誤：

- NPC 姓名／別名互相衝突：提醒，避免人物召回與狀態合併。
- 人物初始數值不是有限數字或超出欄位上下限：阻擋本機試演，要求作者重新儲存合法值。
- 自動追蹤欄位沒有更新依據：資訊提示；只有實測亂跳時才需要補規則。
- 已移除欄位或人物留下的初始值：資訊提示並保留；這是 P1 的可恢復相容設計，不自動刪除。

## 驗收

- Core：`tests/character-studio-rehearsal-core.cjs`、`tests/bao-doctor-core.cjs`。
- Browser：`tests/e2e/character-studio-rehearsal.spec.cjs`，覆蓋 390px／1280px、預覽、Doctor、本機持久化、精準作品深連結與返回入口。
- P0／P1 回歸：初始 NPC 編輯器與共用七組狀態模板測試維持通過。
- 瀏覽器 viewport 不是實體手機鍵盤或真機驗證；本階段也不執行付費模型實測。
