# 故事內釐清：一輪快捷操作

## 需求
玩家在複雜群像、懸疑或長篇故事中偶爾不清楚現在發生什麼時，應能請求 AI 釐清當前局勢，而不是繼續堆疊新伏筆、把關鍵秘密提前揭露，或直接跳出玩家角色的可知視角。

## UI 與操作
- 進入任一故事 →「快捷指令」→ 常用 →「釐清目前局勢」。
- 指令只會**填入輸入框，沒有自動送出**；玩家可先修改或取消。只有玩家真的送出，才會使用現有正文模型處理本輪。
- 不修改原本的「回顧最近事件」，後者側重時間上的最近事件；「釐清目前局勢」著重玩家角色此刻能掌握的線索、在場人物、位置、已知前因與可選方向。
- 只在這一輪有效，不做新記憶分類器、世界狀態重建、常駐追蹤器、額外 Provider 請求或背景推理任務。

## 資訊與敘事邊界
- 僅依玩家角色當下可以看到、聽到或已被告知的內容釐清。由合乎角色知情範圍的 NPC 自然說明，或透過可觀察細節和簡短場景敘述。
- 不把導演筆記、未公開 Canon、幕後真相、其他角色私人知識當成玩家角色已知。情節尚未確立的部分保留未知；必要時可以留待玩家詢問、調查，而不是捏造答案。
- 不改寫已確立時間、位置、NPC 意志或物理後果；不為了幫玩家釐清而強塞新危機，也不替玩家選擇下一步。
- 敘事提示無法構成硬式模型資訊隔離；本 PR 驗證請求內容和操作路徑，真實 LLM 是否符合預期仍需額外對話評估。

## 技術與成本
只在 `BAOStoryQuickCommandsCore.BUILT_INS` 增加一條短指令，受現有清理／去重／分組／填入器管理。沒有改動 `App.buildMessages`、快取的 stable system 區、`GameState`、記憶模型、世界模型或計費。玩家不點就完全不增加任何 prompt token；按下也只是把原本可手動輸入的文字填入 composer。

驗收：`tests/story-quick-commands-core.cjs` 確認 built-in 唯一性、界限、摘要計數與指令邊界；`tests/e2e/story-quick-commands.spec.cjs` 在手機視窗確認指令可見、點選只填入不送出、其他快捷指令及原本自訂指令流程仍可用。全站 CI 審查其他可能受內建指令計數影響的測試。
