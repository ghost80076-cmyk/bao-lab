# 玩家與作者旅程 UX 稽核：第一批

基準：main `ea3693b6`（含 #863）。這是程式路徑稽核與第一批修正，不代表已完成全站實機視覺驗收。

目標：沿「找作品 → 開局連線 → Story → Stage/Phone → Control → 存檔續玩」及「建卡 → 核心/開場 → 世界/互動 UI → 預覽 → 匯出」檢查交接品質。不新增 Shell、資料 schema、設定來源或模型請求。

| 類別 | 主線證據與判斷 | 本批處理／後續驗收 |
|---|---|---|
| 重複入口 | 創作室 topbar 的「返回首頁」與「探索角色」均為 `./`，文案暗示不同目的地。作品搜尋已有 discoveryTools 存在時刪除 fallback 的保護。 | 移除誤導的探索連結，保留品牌及明確的返回首頁。搜尋入口沿用既有單一 owner。 |
| 資訊密度 | `character-studio-lifecycle.js` 將四格生命週期及建議下一步插在整個 form 前，與六步專注流程競爭。 | 將原節點移到 finish 階段；全部欄位仍能查看，舊頁面缺少 finish 時保留原 fallback。 |
| 文案 | 空草稿提示仍要求按已改名的「新建角色卡」。 | 改為角色作品／世界作品／匯入作品，並說明這裡列的是已儲存草稿。 |

## 驗證與限制

新增至既有 `character-studio-flow.spec.cjs`，CI 的 product-explore 群組會執行：

- 320×568、390×844、1280×900：基本步驟不出現生命週期，finish 可查看、預覽，回編輯後隱藏。
- 修改名稱後舊預覽失效，重新預覽顯示最新內容；全部欄位仍可用。
- 空草稿文字、返回入口數量、手機觸控高度、短視窗取消 sticky、頁面橫向 overflow。
- 每個尺寸輸出 `test-results/studio-journey-*.png` 供視覺覆核。
- 既有 lifecycle 回歸調整為從 finish 查看公開狀態；草稿保存、安裝、封存與匯出沿用原流程。

本機已跑 JS 語法、flow/lifecycle core 與 diff whitespace 檢查。兩個瀏覽器都無法連本機預覽，Playwright Chromium 下載取得損壞檔案，因此不把本機 E2E 或畫面驗收記為通過；瀏覽器結果以此 PR 的 CI 為準。

## 尚待收斂的完整旅程驗收

1. 首次開啟／已有故事／搜尋無結果三種入口，跨 320、390、820、1280px 檢查首屏目的與返回位置。
2. BYOK、燈火、本機模型的缺資料提示與快速／完整設定切換；不得產生真實付費請求。
3. Story、Terminal、RPG、Scene、Phone 舞臺：同樣的導航任務，對照資訊密度、閱讀寬度與短視窗退場。
4. Control 開 manager 再返回故事；Phone 通知、已讀保存與續玩，沿用現有測試驗證資料不重置。
5. 作者完成作品後實際走預覽、匯出、匯入及本機安裝；確認各階段的空狀態與失敗提示。

上述尚未做完的部分不能因架構已有對應測試，就宣稱本輪全站 UX 已驗收完成。第一批只交付有程式證據的作者流程修正。
