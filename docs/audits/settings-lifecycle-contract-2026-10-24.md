# 選項生效稽核：生命週期、輔助請求與資料範圍

接續 #820、#822、#825。原始驗收目標是選項從設定、儲存與還原到實際模型請求皆可追溯；CI 綠燈不等於所有 LLM 都會遵從規則。

## 本次發現與修復

| 問題 | 原行為 | 修正後 |
| --- | --- | --- |
| 瀏覽器偏好被故事存檔回捲 | 每次讀取故事覆蓋人稱、回覆語言、外觀及新故事起始偏好 | 已存在的欄位保留；新裝置或缺少的欄位由備份補入。人物演繹等故事選項仍跟隨故事；手動記憶始終依故事還原 |
| 離線世界預覽仍可能呼叫顧問 | 有效 API 殘留、解讀開啟時，前置階段可能先送出 | 離線與 demo 預覽不送解讀／場外人格請求，包括手動評論 |
| 相關世界模組被閱讀模式阻擋 | 單角色沉浸＋純文字時即使命中也省略 | 依模組 core/relevant/ui_only、關鍵詞與預算決定；畫面模式不再使選用資料失效 |
| 停用的人物欄位仍啟動整理 | 欄位系統 enabled=false，但內部 track=true 仍讓一般故事啟用狀態模型 | 主開關關閉後不以這些欄位啟動狀態呼叫；仍保留獨立的世界／狀態追蹤選擇 |

偏好還原繼續使用原有交易與失敗回復。`restoreBrowserPreferences: true` 保留給明確的完整偏好復原，所有 restore wrapper 都轉交參數；一般讀檔不使用它。瀏覽器首次外觀遷移可能只建立 appearance，不能把這個自動產生的部分設定誤認為所有回覆偏好已存在。

## 輔助呼叫矩陣

使用正式頁面與 App.sendMessage，僅攔截模型 HTTP 回傳，不實際花費額度。

| 操作 | 呼叫規則 |
| --- | --- |
| 普通故事、未啟用輔助 | 正文 1 次 |
| 前置解讀 | 正文前最多 1 次；結果只加入本輪 user 的低優先參考，不改穩定前綴。隱藏摘要仍會生成／計費 |
| 後置解讀 | 正文成功後最多 1 次；不寫回正文、主故事記憶或狀態 |
| 場外人格 | 正文成功後全部啟用人格共用 1 次；不以人格數量倍增請求 |
| 三種輔助組合 | 驗證全部 8 組；目前實際順序為前置解讀 → 正文 → 場外人格 → 後置解讀 |
| 主請求失敗 | 已執行的前置顧問仍可能計費；不執行後置／場外評論 |
| 輔助失敗 | 不刪正文，不把輔助內容存成劇情；retryEnabled=false 的測試不重複呼叫 |
| demo／離線預覽／缺少 Key | 輔助 0 次 |
| 空輸入、切換 MOD 指令、重繪／檢視 | 模型 0 次 |
| 智慧摘要 | 達到輪數與整理門檻才呼叫；full 模式不摘要。獨立路由使用獨立模型／Key |
| 同模型狀態 | 狀態附錄與正文共用 1 次；缺少附錄不偷偷補送獨立請求 |
| 獨立狀態 | 依 stateInterval 批次整理；只送設定的獨立路由 |
| 重新生成／AI 改寫 | 完整故事 builder；不自動另跑前後置解讀或場外評論。核對介面已明示範圍 |

`auxiliary-request-contract.spec.cjs` 執行上述正常／失敗／路由測試；既有記憶修復、預算、重試與中止測試繼續驗證例外路徑。這裡的「一次」指一個邏輯請求；一般模式開啟 transport retry 時仍可能重送，摘要格式無效時也可能另有修復請求，不能把此表當成固定帳單。

世界模組的追蹤頻率有路徑差異：獨立整理器在每次批次啟動時遞增 tick，高頻每次、中頻命中或偶數次、低頻命中或每四次；同模型合併則每輪選取有關模組，高頻增加優先分數，中／低頻目前沒有額外間隔差異。摘要已明示這項限制，不能把 4 個 tracker tick 當成所有模式都隔 4 輪。

## UI 與驗收界線

故事總覽新增逐項世界模組與人物欄位範圍，以及已安裝作者介面的獨立權限。依流程執行的項目仍不冒稱「請求含此規則」。輔助 MOD 明示一般送出、修訂與本機預覽的差別。

本矩陣驗證平台提供的列舉選項、輸送與儲存契約。任意作者腳本、任意自然語言自訂指令的所有語義衝突、任意多選組合的模型遵循率，仍不能由有限測試宣稱完全保證；需要依實際輸出與檢視器證據診斷。
