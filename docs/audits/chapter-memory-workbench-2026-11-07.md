# 章節記憶工作台｜手動審閱與保存

日期：2026-11-07。基於 #941 的 source-bound 章節核心；接續 #939、#940 的成本量測，不重做智慧摘要、事件記憶、Canon 或 Context Pack。

## 本輪可使用的功能

- 記憶工作台新增「章節回憶」分頁；簡化版保留四個玩家導向分頁（記憶狀態、必記事項、章節回憶、劇情檔案）。
- 從目前故事中的連續玩家／助手對話建立最多 20 輪的章節視窗。開場白、工具訊息、不完整回合不會猜測成完整事件。
- 玩家可展開原文、手動填章節摘要與關鍵詞，指定 shared／actors／exclude 知情範圍。必須勾選來源核對確認才接受。
- 已知角色名稱正規化及不在場／混合角色的隔離沿用 BAOEpisodicMemory；未核准摘要絕不提供給任何模型。
- 狀態列表即時顯示章節來源有效／失效；明確刪除需要使用者確認，不會連帶刪除原文或自動摘要。
- 每次保存透過 BAOMemoryCore.commitState + Shared StoryMaintenanceLock + App.saveStory + Storage.flush + Storage.loadStory + BAOStorageWriteGuard.verify 檢查；故障、故事切換、來源失效或正在生成時停止，必要時還原原始 state。

## 資料與模型隔離

章節資料只放在 GameState.current.chapterMemory，沿用 Storage 的故事狀態備份與載入。沒有新雲端資料庫，也不將摘要寫入全域偏好。

**沒有任何 API 呼叫、每輪 Prompt 注入、背景蒸餾或自動更改原有智慧摘要行為。** 這一階段的頁面只是手動存檔和本地審閱；還不能宣稱已替玩家節省 Token。

## 驗收門檻

- 單元測試：來源視窗、開場白、不完整回合、可保存／讀回、明確刪除、儲存拒絕、IndexedDB 失敗、verify 失敗、故事切換、角色權限失效、既有來源改寫。
- Playwright 390px + 1280px：四分頁、檢查原文、角色知情核准、保存、匯出／讀回相同狀態來源、來源改寫後停止召回、畫面不溢出。
- Core Tests、Regression impact gate、Fast Browser E2E 全面通過才考慮合併。
