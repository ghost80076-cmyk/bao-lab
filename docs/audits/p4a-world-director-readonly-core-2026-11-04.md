# P4a — 世界事件判斷與連續性審核的無副作用核心

依據：`docs/ai-director-experiment.md`、現有 `js/world-clock.js` 和 P1～P3 的資料來源／知情保護。

## 本批已實作

- `js/world-director-core.js` 是獨立可測的 UMD/CommonJS 純函式；不讀瀏覽器儲存、不呼叫 LLM、不修改故事狀態。
- `plan(state)` 只列出 World Clock 已到期且仍為 pending 的可考慮事件。候選值固定是 `action: 'review'`；**不代表已發生、不代表必須演出，也不能自行揭露 NPC 的秘密**。沒有世界時鐘則回傳空清單。
- `reviewClockPatch(state, patch)` 能發現未知事件、已關閉事件重複關閉、互斥 resolve/cancel 及無效時間增量；缺少證據會要求審閱。傳入 evidenceIds 僅表示呼叫端已提供來源識別，**核心尚不驗證識別對應的實際原文**。
- `compare(before, after)` 偵測世界時鐘倒退、終結事件重新開啟，以及待辦意外消失／期限變動需審閱。
- Node 單元回歸涵蓋安靜回合、到期候選、不可逆狀態、禁止無據自動完成和不修改來源物件；已加入 Core tests。

## 刻意尚未包含

- 本批**沒有掛上正式 App 請求／State PATCH 管線、沒有新增玩家 UI、沒有改變世界時鐘或摘要結果**。此 PR 只能視為 **P4a 可測試的底層實作**，不能宣稱整個 P4 已完成。
- 不將到期排程視為必然發生；不替玩家行動；不將幕後資訊塞入共享 Prompt；不做每輪 LLM Director。
- 沒有自然語言的語意矛盾判斷，也無法從角色回覆直接證明事件真的發生。正式接線前，必須接上原始 message ID + 簽章與角色知情校驗，再進入審閱／決策 UI。
- 舊世界存檔不自動建立世界時鐘；主線 `GameState` 和世界模組 schema 不遷移。

## 後續 P4b 驗收門檻

1. 在既有 World State 完成驗證／來源 guard 後，由實際完整回合的快照產生只讀審核結果，避免過期非同步任務。
2. 保存「候選、原因碼、證據與結果」的最小資料，回溯、分支、改寫或來源缺失時失效；不能為劇情強行推進時間或完成事件。
3. 僅向玩家顯示有權閱讀的結果；幕後事件不能直接進主 RP 共用 Prompt。
4. 若導入模型輔助矛盾偵測，必須顯示是否額外付費、預設關閉，任何修正須有玩家明確確認；保護 P1～P3 的資料隔離。
5. 測試從 30–40 輪錯位、120 輪摘要、回溯、長期等待、政策阻擋及不同模式的 quiet turn 開始，不依靠模型運氣。

本批只有新純函式、新測試、CI 接線與文件。撤銷 PR 即可，不需要玩家存檔遷移。
