# 夜灣玩家／作者完整旅程 UX 覆核

## 基準與驗收方式

基準為 `003ea727`：#864（創作流程收斂）與 #865（包包情境任務、手機書架高度）皆已合併。這次不再把先前 PR 的自動測試通過，當成全站畫面已看過。

使用 `tests/e2e/journey-visual-audit.spec.cjs` 產生真實 Chromium 截圖與每張畫面的 geometry JSON，再下載 CI 產物檢視。畫面擷取等待原生平滑捲動停止，避免把轉場中途的留白誤判為穩定版面。截圖、首次失敗紀錄、修正後 CI 及最終產物連結集中於 PR #866。

範圍是這次討論的玩家／作者產品：首頁、我的、探索、作品介紹、開局、故事、舞臺、Phone、控制中心、記憶、書架與創作室，加上 16 個公開獨立頁面。沒有登入管理後台、執行付款或呼叫真實故事模型。舞臺使用固定測試作品，確認平台構圖與交接；不宣稱覆蓋所有作者可能輸入的內容。

## 針對性回歸

- `character-studio-flow.spec.cjs`：從全部欄位返回專注模式後，目前步驟必須完整落在橫向導航可視範圍。
- `phone-ui.spec.cjs`：關閉與 home 的 44px 點擊區、短視窗可達性、模態背景隔離、Tab 不離開 Phone、關閉後回 opener。
- `memory-workbench-theme.spec.cjs`：模態語意、Tab／Escape、原入口焦點、關閉後 config 與 GameState 不變。
- `journey-visual-audit.spec.cjs`：每個畫面記錄尺寸與可見操作；所有畫面 document 不可水平溢出。這是 geometry 驗證，不能取代人工看圖，因此兩種證據分別保留。
- 既有 Phone 已讀／隱藏內容、存檔備份、Story/Control、開局、Stage 邊界、核心載入契約由原 CI 檢查維持。

## 實體鍵盤驗收的邊界

瀏覽器中的實際 Tab／Shift+Tab／Escape 與縮短視窗都可驗證；縮短視窗不是 iOS／Android 軟鍵盤，也不是實機驗收。本環境沒有可控制的實體手機，因此以下四項仍屬實機檢查：

1. iPhone Safari 鍵盤彈出與收起時，Story 輸入、送出、讀取位置是否穩定。
2. Android Chrome／Samsung Internet 對 layout viewport 與 visualViewport 同時縮小時的輸入位置。
3. Phone 聊天輸入與回故事後的鍵盤切換、手勢安全區。
4. 創作室多行編輯的「完成」與切換階段，是否在實際鍵盤下仍可達。

不把這四項記成已通過，也不因此把已完成的八類桌機／手機瀏覽器稽核改寫成尚未做過。最終 CI head、畫面數與覆核結果以 PR 說明為準。
