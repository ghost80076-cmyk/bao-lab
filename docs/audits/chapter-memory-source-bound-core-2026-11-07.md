# 有來源的章節記憶：核心第一階段

日期：2026-11-07。接續 Token 基線 #939、合成成本實驗 #940。本 PR 只新增本地純函式核心，不啟用正式對話章節載入、AI 章節生成、自動蒸餾、資料庫或狀態更新。

## 既有記憶基礎

智慧摘要（Chat.context / maybeSummarize）已保留未成功整理前的原文；Episodic Memory 管理事件、場景、證據與 NPC 知情；SummaryKnowledgeCore 管理玩家逐段確認；MemoryCore.commitState 支援持久化驗證。本階段不取代上述機制，而是定義可以核對來源的獨立章節。

## 核心契約

1. **完整來源**：proof(messages,start,end) 只接受完整玩家／助手交替回合，單章最多 60 輪、訊息 ID 全域唯一。記錄起迄 index、首末 ID 和全文雙雜湊來源指紋，不將整份原文複製到章節索引。
2. **需明確確認**：createDraft 永遠未核准。approve 明確要求 shared／actors／exclude；未來 UI 必須由玩家主動確認，不能把 AI 整理稿自動視為所有人知道的客觀事實。
3. **知情隔離**：私人章節須經 BAOEpisodicMemory.resolveActor 正規化及歧義驗證。recall 不接受自報的「只有誰在場」，而是以 BAOEpisodicMemory.audience 從目前場景取得真實觀眾，再以 canRead 判定。缺解析器、混合觀眾不符、exclude 都不得透露私人章節。
4. **回溯防護**：每次召回都驗證核准版與原文來源。任何原文編輯、重排、回溯、ID 重複或核准後文字改變都失效。audit 只標記失效，不自動刪除資料。
5. **選擇性有界召回**：非空查詢有匹配才召回；預設最多兩章，最多三章、4,000 字；整章超過預算就跳過，不截斷內容，也不每輪灌入全部章節。
6. **容量與重疊**：最多 200 章；相同章節可重複提交而不膨脹，來源重疊、過量均拒絕而不丟棄舊章節。

## 未完成的部分

- 這個 Hash 是本地來源變更偵測，不是防惡意竄改的加密簽章。未來跨端或匯入需更強的指紋與資料驗證。
- 來源吻合不代表摘要語意正確，仍須人工審閱；章節來源不能代替角色知情、關係方向與後續狀態的驗證。
- 對特殊非交替訊息、工具訊息、開場非完整回合採拒絕而不是猜測。
- **尚未加入網站 Runtime**，玩家目前沒有章節管理 UI，且每輪 Prompt 完全不變；這個 PR 本身不證明省 Token。

## 測試和下一階段

tests/chapter-memory-core.cjs 覆蓋 shared／actors／exclude、混合場景、別名歧義、回溯、刪除、重排、重複 ID、內容篡改、章節重疊、按需上限與 100／500／1,000 輪的本地索引。

下一階段應做玩家選用的章節審閱與持久化，沿用 MemoryCore.commitState，再驗證匯入、匯出、回溯和瀏覽器還原。最後才考慮可選 Context 注入，並衡量完整模型費用與角色召回正確性；**不得默認開啟付費蒸餾**。
