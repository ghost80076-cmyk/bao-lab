# 共用狀態流程全站稽核

基準：主線 `a83878c8384bb8e398f9cf62d119681c68f6f009`（#879–#882）。範圍是全站共用的故事／狀態一致性，不將單卡修復或 CI 綠燈解釋為所有模型必定遵循。

## 修復

| 流程 | 查到的問題 | 處理方式 |
| --- | --- | --- |
| 手機＋合併狀態 | 手機區塊被存入比對來源，Chat.add 去掉區塊後 turn mismatch；區塊放在狀態後面則被截掉 | 保留狀態區塊外的完整資料；用與實際提交相同的可信清理方式比對正文 |
| 內部狀態回聲清理 | UI 移除尾端內部 JSON，狀態比對仍看未清理原文 | 同樣遵守既有主請求清理條件，不放寬任意文字匹配 |
| 重生成／AI 改寫 | __storyTool 跳過狀態協定；恢復 revisionBase 又換了 owner，原附錄無法套用 | 只有正式修訂參與合併；即使正文相同也以新版本識別核對狀態。以一次性 token、來源前綴、故事 lineage、設定與角色綁定回傳值，再交給選定版本處理；不新增狀態請求 |
| 修訂手機資料 | 替換文字不經 Chat.add，手機區塊殘留正文／無法切換 | 將已驗證的手機 patch 與版本配對，從同一 revisionBase 套用；原版本快照只在實際修訂時保存，避免每輪額外複製整份世界 |
| 人物自訂欄位 | 設定允許作者 24＋玩家 24，合併請求卻只傳前 24 | 使用既有完整正規化 schema，尊重停用；人物追蹤欄位漏檢時保留待補，不能冒充全部完成 |
| 修訂競態 | API 回來後未再驗證對話來源；暫時 rewind 的還原可能覆蓋本機扣款 | 回覆完成後重新核對來源／設定／操作版本；過期結果取消，還原時保留本機新操作與目前玩家設定 |
| 手動重建手機 | 只重建世界資料，手機保存來源未重播 | 根據目前選定版本已保存的 phonePatch 及其 revisionBase 重建；保留通知已讀。來源有缺口則保留原資料並明示部分完成，不讓狀態模型編造手機事件 |
| LM Studio JSON | 本機傳輸漏掉 finish_reason，截斷可能被視為成功 | 保留供應商終止原因，沿用共用截斷／阻擋判斷 |
| 記憶摘要 | 即使供應商回報截斷／阻擋，可解析 JSON 仍可能前移摘要游標 | 摘要與格式修復都先檢查終止原因；失敗時不替換舊摘要、不消耗原文，也不因已知截斷另發格式修復請求 |

## 驗證範圍

| 層面 | 證據與界線 |
| --- | --- |
| 全作品請求 | 依首頁＋community manifest 全部分頁去重，目前 74 個公開作品；每個作品用正式正規化、schema、傳輸、解析與更新管線核對所有自動模組。這是確定性協定驗證，沒有逐作付費長聊 |
| 人物欄位 | 作者 24＋玩家 24；第 48 欄可更新，未核對欄位保持 partial，數值 0／型別錯誤／停用另有核心測試 |
| 一般／獨立狀態 | 同模型一次請求；獨立路由依既有間隔，正確接受更新並拒絕截斷資料 |
| 介面 | Reader、原生狀態頁、Gameplay、RPG Dashboard、Scene RPG、Terminal、Phone；44 個原生檔案介面於桌機與手機檢查；沒有修改作者作品內容 |
| 保存／歷史 | 重生成、改寫、原版本切換、保存重載、真正的歷史 checkpoint 回溯、原故事線恢復；新增金錢＋手機跨層案例 |
| 記憶／傳輸 | 完整 Core workflow；三協定、SSE 完成訊號、首次摘要邊界、40／80／120 輪既有測試，另加截斷與阻擋不消耗原文的檢查 |
| 作者／管理頁 | 原生／扁平匯入、創作室編輯／匯出、管理 payload 與 Worker 發佈格式的既有往返測試；實際上架操作未被當成驗證步驟 |
| Creator MCP | 唯讀檢查 `yorubay-creator-mcp` 0.20.0，commit `e0582ecd83ffa877485ee598c3983d256ba7476e` 的 export／MCP schema／migration；world_modules、initial_state、Phone 資料格式未因本批改變，狀態附錄協定仍由前端負責。本批未改動 MCP 服務，也未執行公開發佈 |
| 後續回歸 | 新增全作品／生命週期 spec 至 Chromium 群組，另以 Firefox／WebKit 獨立 job 執行；回溯測試改用目前預覽與更多操作流程並納入快速 CI |

## 保留限制

深度重建仍為有限原文與既有摘要，不是全史交易帳本。缺少證據的資料保持未確認；舊手機紀錄沒有保存來源時不能憑空復原。模型仍負責語意、因果與數學判斷，結構驗證不是模型遵循保證。瀏覽器測試使用模擬回覆與本機伺服器，未使用玩家金鑰，也不代表實體手機鍵盤／真實供應商長聊驗收。
