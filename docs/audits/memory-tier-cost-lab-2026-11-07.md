# 長篇記憶 P1｜分層策略成本實驗室（合成驗收）

日期：2026-11-07。本次僅新增 **read-only** 開發測試與量測腳本，不修改執行期故事 Prompt、既有自動記憶、事件索引、世界書、狀態、帳務、模型路由或任何玩家存檔。

## 目的

P0 已在上下文狀態中新增以 UTF-8 位元組比例分攤服務商總輸入 Token 的粗估。要決定是否推行「近期原文／獨立章節摘要／長期大綱」之前，需要確認：**多層章節記憶不應每輪全部注入，否則可能比現有智慧摘要更昂貴**。

這個實驗用 100、500、1,000 輪合成故事，直接執行主程式 `Chat.context` 的 `smart` 和 `full` 路徑。先將完整回合的既有來源視為已成功摘要，凍結同一近期原文，再比較下列**可序列化訊息的 UTF-8 位元組**：

| 比較路徑 | 內容 | 注意 |
|---|---|---|
| full | 實際 `Chat.context(full)` | 原始歷史量 |
| smart | 實際 `Chat.context(smart)` | 現有智慧摘要，含近期原文 |
| naive all-chapters | 假設每輪注入所有已建章節加近期原文 | 反例，應避免 |
| selective candidate | 假設僅注入小份大綱、符合查詢且來源可核對的一章加同一近期原文 | 候選示意，尚未接入 Runtime |

章節由本機測試以固定區間與**合成示例文字**生成，不涉及實際 AI 提取、章節分界語意判斷或長期大綱品質。每章核對來源完整回合、訊息順序、ID、角色及內容指紋；原文回溯、重排、改寫或消失均阻止召回。候選模式對比時保留完全相同的近期原文。

## 執行

```bash
node scripts/memory-tier-cost-lab.cjs
node tests/memory-tier-cost-lab-core.cjs
```

所有資料均為合成測試用例，沒有玩家資料、API Key、付費呼叫、獨立模型、記憶整理、資料傳輸或持久化。輸出的 `smartBytes`、`selectiveBytes` 等為**單次歷史上下文序列化位元組**，不是 Provider Token、價格、整輪模型使用量，也不包含角色設定／世界書／動態狀態等上游層。

## 尚未滿足的上線條件

- 不可用合成「章節摘要」冒充實際召回品質。需要保留組與真實長篇樣本的**有來源**重要事件、伏筆、承諾、NPC 知情、關係方向與分支還原驗收。
- 不可只比較單輪輸入。實際成本須計入正文、摘要、重試、蒸餾、狀態、Cache read/write 與供應商差異，並收集 provider 返回的 usage；不使用本報告的位元組直接推算帳單。
- 必須保留 Canon、Context Pack、必記事項與事件權限來源，避免將客觀秘密寫入所有角色共享的大綱。
- 若分層候選在完整成本、召回精度、知情範圍或分支相容性任一項退步，不能切換現有故事預設。

**本 PR 只作為決策基線；不建立付費蒸餾排程，也不宣稱已降低夜灣的 Token 成本。**
