# P0｜長篇記憶 Token 效率：量測基線

日期：2026-11-07。範圍限定為既有上下文診斷的本機觀測；此 PR 不引入新記憶層、改寫 Prompt、裁減來源、呼叫更多模型或改動存檔格式。

## 目前實作與已確認界線

- `js/prompt-cache.js` 建立一般故事最終訊息：固定規則、記憶區、原始歷史及動態規則／最新玩家輸入；其他 send wrapper 可能補上狀態等訊息。
- `js/context-inspector.js` 在 API 包裝器內擷取一般故事／重生成／AI 改寫的實際送出訊息。既有來源指紋、故事擁有者及重設檢查仍生效；記憶、狀態、連線測試及其他 helper 不覆蓋故事快照。
- `js/context-efficiency-core.js` 已用段落標題與訊息位置估算角色與平台、世界／NPC、記憶、世界書、近期原文及本輪輸入六類；分類是 best-effort，文字中的相似標題仍可能影響歸屬。
- 既有自動摘要、事件／場景召回、Context Pack、Canon、分批續作、記憶工作鎖／回溯保護不改動。沒有直接從角色卡或世界書推定可安全刪除的內容。

## 本次新增量測

1. 保留原 UTF-16 字元統計，另外為各分類計算 UTF-8 位元組權重及總位元組，涵蓋中文與 emoji。
2. **只有**成功的故事請求回傳有效的 `usage.input_tokens`，才用位元組占比將這個已回報總量「比例分攤」到六層，顯示「約 Token」。未回報、不合法、零 Token 或空訊息時不分攤；不以固定字元／Token 比率臆測。
3. 玩家於「控制中心 → 上下文狀態 → 本輪輸入組成」檢視總輸入、各層占比與疑似重複。數值只保留在現有 WeakMap 的當前請求診斷，不進本地故事存檔、備份、網路分析服務或新 API。
4. 顯示說明明確區別：總輸入是 Provider 回報；層級 Token 為 **粗略分攤**，不是 tokenizer 的分段測值，也無法代表快取折抵、不同單價或 Provider 內部序列化開銷。

## P0 驗收與下一階段決策門檻

- Core 測試：所有訊息的字元、UTF-8 bytes 均被分到且只分到一層；中文／emoji 不錯算；無 usage 不顯示估算；有 usage 才保留總量與分層粗估；來源文字、API key 不能滲入數值快照。
- 接口測試：重生成、AI 改寫、故事切換、編輯、回溯、helper 請求和 reset 不影響既有擷取界線；不新增模型呼叫。
- 瀏覽器測試：手機／桌機能閱讀中文標示且不溢出；Provider 缺失 usage 時不得假裝已有精確 Token；分類圖及快取敘述不得宣稱節費。
- CI 與正式站：測試、PR、合併、Pages、正式站 smoke 是不同步驟；PR 與本文件本身不代表上線。

**P1 是否啟動章節摘要，需先有實際比較證據**。請以可重現的 100／500／1,000 輪故事樣本，固定角色卡、世界書、模型、輸出長度與故事事件分布，比較正常智慧摘要及候選分層方案的：
- 主故事每輪實際輸入／輸出與快取 Token；
- 自動摘要、狀態整理、蒸餾的額外呼叫、重試與總費用；
- 重要事件與未解線索召回、角色知情、分支回溯及來源證據完整性。

資料不足時**不**將分層壓縮自動套到玩家故事，也不預設每輪 Token 或費用一定下降。若主要輸入來自固定規則、世界書與狀態而非長期摘要，應先處理該來源的可見冗餘與動態選取；不能為了測量就刪除玩家內容。
