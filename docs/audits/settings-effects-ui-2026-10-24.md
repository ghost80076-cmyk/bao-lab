# 設定範圍與請求證據 UI

接續 PR #820 的組裝稽核，沿用故事總覽與本輪上下文檢視器。這次只加入本機診斷與說明，不修改選項的儲存方式、預設、組裝順序或模型任務。

## 玩家入口

- 故事總覽 →「設定範圍與生效狀態」。依敘事與指令、瀏覽器回覆偏好、世界與角色、記憶與輔助、畫面與閱讀分組；自訂長期指令逐條列出。
- 摘要內「核對最近送出內容」連到原有上下文檢視器，新增「這次請求的設定核對」。這裡保留送出當時的選擇，不用目前的新設定冒充舊請求。
- 今晚的故事／回覆設定各自顯示作用範圍與儲存時機，保留原有取消、套用與預設流程。

## 分開呈現兩種狀態

| 目前設定 | 最近送出的核對結果 |
| --- | --- |
| 下次回覆套用 | 請求含此規則／未找到相符規則 |
| 等待觸發 | 本次未觸發／請求含此規則 |
| 依作品安排 | 未額外加規則 |
| 由其他設定取代 | 由其他設定取代 |
| 不加入請求 | 已省略，並顯示停用／重複／分類排除原因 |
| 僅影響畫面 | 僅影響畫面 |
| 依流程執行 | 此項未逐字核對；需查看其模型／記憶流程 |
| 任一選擇已改變 | 設定已變更，待下次送出 |

請求包含規則不代表 LLM 一定遵循；請求成功／失敗另行顯示。剛開啟或重新載入、切到其他故事而沒有記錄時，顯示尚無送出紀錄。

## 實際範圍與優先次序

- 玩家角色演繹與觀賞授權依目前故事；舊故事不繼承瀏覽器的共創／觀賞授權。
- 舊故事沒有 narrative 時，其他敘事偏好會沿用瀏覽器起始偏好。摘要明示這個來源；查看不自動補寫 narrative。
- 故事篇幅優先於瀏覽器回覆長度；親密場景加強開啟時，原親密處理方向標為取代，保留其原選擇。
- 敘事人稱、台詞格式、AI 回覆語言目前仍為瀏覽器範圍，與網站介面語言分開。
- 世界書、角色身份、手機偏好依作品預設與玩家故事覆寫顯示來源；世界書待條件／知情／預算判定，開啟不等於每輪加入。
- 全文模式略過另行事件回憶；記憶整理、人物世界狀態、雙向解讀與場外人格的輔助請求，以條件式流程說明，不冒稱已成功呼叫。
- 字體外觀、網站語言、文字替換及狀態欄顯示屬呈現；故事排版另含輸出格式要求。隱藏狀態欄不等於關閉追蹤。

## 技術與驗證

`settings-effects` 讀取正式偏好解析器與規則產生器。敘事項目的核對字串由正式 buildPrompt 的差異取得，人稱／語言／篇幅由 player-settings 的唯讀接口提供；不另寫一套模型規則。核對 system 與最新 user，排除歷史文字造成的假命中。

送出時在既有 context-inspector 內擷取不可變的選擇與證據；不新增 API wrapper、不修改 messages，也不保存金鑰、路由設定或回覆文字。診斷例外不阻擋原請求。記錄沿用記憶體／故事隔離生命週期，不寫入存檔、備份或遙測。

驗證包含：真實解析器的舊故事授權與篇幅優先、指令排除原因、送出後修改與還原、失敗請求、模組例外隔離、HTML escaping，以及檢視前後 prompt/config/state/localStorage 不變。瀏覽器測試涵蓋 320／390／1440px 與既有偏好、快取和故事總覽回歸。

尚未逐字核對的獨立任務、所有世界模組個別欄位及作者正則權限，仍使用對應工具的明細；本摘要不代替模型遵循率評估。

## 修訂請求的核對補完

最近請求現在涵蓋一般故事回覆、重新生成與 AI 改寫，並在摘要與檢視器標明類型。行動靈感、圖片提示詞、記憶整理、狀態整理、解讀與連線測試仍不覆蓋這份紀錄；這些獨立任務的觸發／成本稽核仍是後續工作。

- 修訂呼叫端使用明確的內部請求類型；不把所有 `__storyTool` 都當成故事回覆。不改 provider body、規則順序或原有模型呼叫數。
- 內部 revision snapshot 會換掉 `GameState.current`，檢視器改以 revision 模組的暫存 lineage 作為弱引用索引。正常狀態回溯與修訂後的派生資料重算維持同一份紀錄；外部匯入／還原、不同故事與 Chat.reset 仍隔離或清除。
- 修訂回覆正式加入版本後，呼叫端一次性重綁來源錨點。只有同一回覆物件、成功請求、未改動的前文與相同訊息長度可綁定。切換其他版本、修改前文或清除對話後，不再顯示這份證據。
- 改寫最後一則 user 包含改寫要求與被拒絕的舊回覆，介面單獨標示。動態規則只在其前一則組裝好的玩家輸入核對，避免任務引用或更早歷史造成假命中；system 核對維持原樣。
- 修訂不取代一般送出的上下文字數比較基準。失敗請求保留失敗狀態與送出內容，不冒充已採用的新版本。

新增 `context-inspector-revision.cjs` 以正式 API pipeline 和 revision snapshot 驗證狀態回溯、正式採用、變更分支、失敗、輔助任務排除與清除。既有手機／桌面 request-feature-contract 瀏覽器測試同步核對兩種修訂的設定證據、動態手機／世界書資料及 UI 類型標示。
