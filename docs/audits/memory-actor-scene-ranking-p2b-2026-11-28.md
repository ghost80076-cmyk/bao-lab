# 記憶 P2b：人物與場景來源輔助排序（原有 hybrid 選用模式）

基準 6bc7636c659f782d6095b3b82265902d9b192798；延續 P2a，僅變更已符合召回條件的候選排序。新增明確已登錄人名／別名匹配（2–20 個漢字或 3–40 個 ASCII 單詞字元，區分大小寫；超過 150 個名稱不使用）；查詢最多 120 字且僅一個可無歧義解析的身份、另有非名稱的字詞。候選可見 claim 必須匹配同一身份且命中主題詞，才有 1 分人物排序訊號。提及不是在場，也不是知情；不從作者設定、NPC 隱藏資料或 event.entities 推斷身份。混合語言、多詞名稱、歧義與多人物查詢不擴張適用範圍。

已可召回的場景若同時有人物及主題訊號，且為未撤回的公開事實或有來源的目擊／告知認知，才取其實際可見 claim 的 evidence ID。非場景候選也必須已相關且可見 claim 命中主題詞，並有重疊可見 evidence，才能獲得 1 分關聯訊號。不使用私密客觀場景範圍、不從場景補授角色權限。傳聞／推論不作連結種子。人物、場景、P2a 上下文依序作同分決勝；原本 lexical / fulltext / RRF 不變。不新增候選、欄位、模型、請求、索引儲存、提示詞或四筆／2400 字上限。預設非 hybrid 模式不變。

新增固定合成測試：明確別名、同來源事件排序、同名物品干擾、無人物、歧義、多人物、缺場景來源、私密客觀範圍、傳聞、已在 prompt 的場景、state 不變。既有 76 案 oracle 不變，兩份 checked-in 報告僅同步 core SHA-256，實際全量結果仍待 CI 重跑核對。不代表真實玩家召回率提升，人物字串不等於語意或關係推理；多角色、同名地點、場景轉換、指代與成本仍需獨立驗證。回退 PR 即可，無資料遷移；core v10→v11。
