# 既有記憶強化 P1b — 提取品質與可檢索線索

## 決策與範圍

基準 main cc953467df6fc40cfc1597698d2a112d7ac9cb1f；#1019 已關閉、未合併，保留 E5 模型研究作為反例（保留集 1/10 召回、0 FP）。本輪不下載模型、不建立向量資料庫、不新增模型呼叫、付費服務或依賴。保留 #1018 基線。

目前 `js/chat.js` 的自動記憶整理每次最多 4 個事件（縮小重試最多 2），每個事件最多 3 個 keywords。既有 recall 已使用這些詞，不需新資料結構。本輪先在同一次自動整理指令中，指定重要事件提取優先序。依使用者回饋撤除主動產生自然近義詞、事件概念的要求，keywords 優先使用有原文依據的具體用語，不替換成文藝詞彙；私密標籤限有共同來源的角色認知，沒有合適詞就少列。所有自動摘要欄位採中性、精簡的事實表述，保留原文重要用語及專名，不仿寫正文文風、添加修辭或把比喻當事實。text／claim 不因檢索詞而改寫。正文模型仍只接收既有回憶區塊，索引關鍵詞及提取指令不直接注入。指令不是對 LLM 輸出真實性的程式驗證。既有角色權限、來源指紋、分支、預算、回退、固定 prompt 前綴和儲存完全不改。關閉事件召回時不加入事件索引提取指令，普通摘要仍遵循中性表述。

## 驗收與成本

新增實際自動整理請求的指令及預算斷言、禁用模式檢查，以及原文線索召回、已知改寫缺口與舊索引相容測試（含錯角色、混合知情、回溯、改寫、無關輸入、已存在記憶）。另確認舊索引中的搜尋同義詞與新提取指令不直接出現在正文 Prompt；這不代表能保證正文生成文風完全不受回憶選擇影響。既有 76 案基線仍應原樣通過；不得修改既有 oracle 或將人工補詞當作實際模型召回提升；改寫缺口留待獨立檢索改進。現有記憶回歸、分支、存檔、路由與前端 loader 版本檢查維持。

新指令增加少量整理 prompt 文字，可能影響單次 token 或既有預檢分批次數；不新增獨立請求、擴大輸出上限或改變排程。不得宣稱已降低費用。歷史事件不自動重掃或改寫，既有索引保持相容。實際各供應商的提取品質、費用、超長篇留存及錯誤率未測；需用相同來源與預算做受控比較，再考慮進一步調整 JavaScript 多層排序。未來成熟語意模型或付費進階服務另案評估，不降低既有功能。

## 回退

只改自動摘要指令、測試與 index.html 的 chat.js 快取版本。無 schema、存檔或 Worker/AWS/帳務變更；正常回退 PR 即可，已生成的合法 keywords 仍是原有格式。
