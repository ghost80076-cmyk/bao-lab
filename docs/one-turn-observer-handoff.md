# 單輪觀賞模式與控制權交接

## 目的
玩家可以在小說合作時偶爾放下手中的角色，由 AI 依既有 Persona 代演一小段日常劇情；下一輪玩家重新輸入具體言行，就回到原本的「玩家主控／敘事補述／小說共創」。這是從社群玩家的「觀賞模式」吸收出的夜灣原生、小範圍實作，不照搬其長篇協定或全輪狀態欄。

## 開啟及使用

1. 在「今晚的故事 → 回覆方式」將 **單輪觀賞模式** 從「關閉（預設）」改為「開放 · 指令才暫時代演」。
2. 在故事對話欄 **單獨輸入** `繼續`、`然後呢`、或 `【觀賞一輪】`。這一輪才會在最新玩家輸入之後附上 **本輪觀賞授權**；模型可以依已確立的玩家人設代演非重大言行、感受和小選擇。
3. 下一輪玩家寫「我推開門」「我說……」等具體言行，即回到既有的 `playerPortrayal`。不需按退出鍵、不會把觀賞視為永久 NPC 資料。
4. 「繼續描寫」是原本快捷指令，內含「不替我做決定」，**不是**觀賞指令；「嗯」「好」、引述命令、混入具體言行、包含多句指令也不會觸發。

## 權限邊界

- 只有新故事經玩家選擇、或舊故事在自己的設定中明確開啟 `config.narrative.observationMode = "one_turn"` 才可觸發。瀏覽器預設值不能替舊故事開權限；不新設永久觀看模式。
- 單輪可代演日常表現；重大承諾、關係確立或決裂、同意、不可逆選擇、死亡決定仍需交回玩家。不得把拒絕轉同意。
- 世界時間、NPC 自主、角色所知與記憶、Canon、角色卡和既有 playerPortrayal 的基準保持原樣。模型遵守程度仍需真實模型驗收。
- 不依靠脆弱的本地全域旗標判斷哪輪曾觀賞；從實際組裝的 **最新玩家輸入** 精確匹配一個完整指令，且必須由故事級選項明示開啟。舊歷史中存在「繼續」不會影響新回合。
- 此次不做無玩家輸入的背景自動生成、不做常駐觀賞、不增加 Provider 或記憶模型呼叫。
- 現有「今晚的故事」仍用原本保存與撤銷機制，切換選項會改一次 stable system prefix，供應商可能需重新暖機；觀賞／交還本身只變動當輪 user 尾端，維持 stable prefix bytes。

## 技術與驗證

- `js/narrative-settings.js`：新增明確 opt-in `observationMode` 欄位、設定 UI、摘要；啟用時生成穩定觀賞例外授權，關閉時保留舊提示詞原樣。
- `js/prompt-orchestrator.js`：在現有組裝的 `【玩家最新輸入】` 區塊精確比對上述三個指令，再把 `【本輪觀賞授權】` 接在最後一則 user 訊息；不額外重送記憶或改 system prompt。
- `tests/narrative-settings-core.cjs`、`tests/narrative-prompt-pipeline-core.cjs`：預設關閉、只對明確授權生效、指定模型請求組裝、單輪交回、穩定前綴、無效設定修復與異常匹配拒絕。
- `tests/e2e/narrative-cache-preservation.spec.cjs`：390px 手機和 1440px 桌面：取消、套用、重開、原有設定保存、模擬繼續／具體言行、無額外模型呼叫。
- `js/site-i18n.js`：繁中、簡中及英文產品文案。
- 不會把合成測試當作真實 Gemini、Claude 或其他模型實聊品質的保證；模型是否遵守交棒與沉浸，仍待實際試聊。
