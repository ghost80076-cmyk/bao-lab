# YoruBay Experience 3.0｜第二十一輪：NPC 名冊、場景參與者與可見關係

日期：2026-10-15。

## 問題
現有 NPC 名冊已正確區分「整份故事人物」與「目前場景在場」，也刻意限制收藏人物時只複製姓名與身分，不讀作者隱藏設定。但當故事人物變多，所有 NPC 混在同一長清單；快速補登永久佔據版面；玩家也必須回到人物狀態頁才能確認已公開的關係狀態。

## 本輪
- 名冊新增本機搜尋：姓名、身分、地點、在場狀態，以及玩家原本就能看到的關係摘要。
- 新增「全部／本場／其他」三個篩選，數量隨目前暫存的場景勾選即時更新。
- 名冊列把姓名、身分、場景狀態、地點分層；已在本場的人物有明確 badge。
- 關係摘要只讀 `visibleFields(config)` 中名稱／key 屬於關係、好感、信任、羈絆、親密類的欄位；玩家已隱藏的欄位與「未確認」值不顯示。沒有新增作者秘密資料讀取。
- 「快速補登 NPC」改成原生 `details`，預設收合，需要時展開。
- 文案改為「全部加入本場／清空本場／儲存本場人物」，避免把尚未儲存的 UI 勾選誤稱為已發生的世界狀態。
- 晨霧／暮玫使用既有 `--yoru-*` 語義色票；夜港維持原方向。
- `character-status-ui.js` 與 CSS 資產版本遞增，避免正式站沿用舊 JS 快取。

## 資料與資訊隔離
搜尋與篩選只存在當前 modal 記憶體。切換勾選時只修改本地 `selected Set`；按下「儲存本場人物」才呼叫既有 `setSceneParticipants()`。關係摘要不讀取作者卡私有欄位，只使用目前狀態欄已允許顯示的欄位。

「收藏人物」仍沿用 `saveVisibleNpcPreset({name, role})`，不因畫面出現關係摘要就把關係、狀態或作者設定複製進人物庫。

## 驗證
在既有 `portable-story-actors.spec.cjs` 增加 390 / 1280px：
- 本場／其他篩選與搜尋。
- 可見「盟友」可被搜尋；被玩家隱藏的測試關係值不出現在 DOM，也不能被搜尋。
- 快速補登預設收合。
- 勾選變更在儲存前不修改 `GameState.current.npcs`。
- 儲存後才更新 presence。
- 晨霧／暮玫 computed background 與無橫向溢出。

不新增 workflow，沿用 product-explore、Core、Firefox/WebKit 與既有人物／世界狀態回歸。
