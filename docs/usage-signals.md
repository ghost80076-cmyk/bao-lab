# 自願遊玩使用訊號

## 範圍與解讀

第一版回答「是否有人進入遊玩、主敘事請求是否成功、是否繼續互動」。不收作品 ID、名稱、分類、模型、金鑰、帳號、提示詞、正文、錯誤原文或 IP，不與帳務紀錄關聯。BYOK 和燈火共用主模型回覆入口，記憶／狀態／工具／輔助／連線測試、示範模式、取消及已切換故事的結果不計。

統計預設關閉。在故事設定及首頁頁尾可開關，也尊重 GPC 和 DNT。這是**自願回報樣本，不是精確玩家數或完整漏斗**。零筆資料可能是未同意、網路阻擋、尚無請求、部署不同步或當日接收上限，不能推論沒有人玩。

以分頁及 UTC 日期去重，同分頁跨作品合計，每日各里程碑最多一次；重整沿用 sessionStorage。新分頁、清除資料或瀏覽器複製分頁行為會影響計數。累積五次指當日同分頁成功的主敘事請求，不保證是同一作品的五輪，重說／繼續等主敘事請求也可能計入。首次成功與首次失敗可同時出現，並非互斥分類或總請求成功率。不回溯補傳同意前的活動。

## 傳輸與免費額度

- 前端將相鄰事件延遲 1.2 秒合併；切離頁面使用 fetch keepalive。不帶 Cookie、Authorization 或 referrer，不使用 sendBeacon（避免攜帶憑證）、不重試、不離線補傳。
- 每批最多四種事件，每個參與分頁每日最多四批。獨立 128-bit 隨機批次碼僅用於重送去重，不作分頁、故事或使用者識別。
- `POST /usage-signals` 沿用 Worker 的 ALLOWED_ORIGIN 檢查，拒絕無 Origin、Cookie、授權標頭、未知欄位、無效日期、重複／未知事件及大於 512 bytes 的內容。
- 全站每天最多接受 **500 批**（UTC），以 D1 交易中的批次去重及計數條件原子限制。每日彙總一列；批次碼只留今日及昨日，彙總保留 30 個 UTC 日。清理隨後續有效回報執行；停用或無人回報時，舊資料不會自行過期，可人工刪除。
- 接收上限限制接受後的儲存增長，**不是帳號總請求／讀取的硬上限，也不是防 DDoS 保證**。無效、重複、超限請求仍消耗 Worker 請求；有效超限請求仍可能查詢 D1。與帳號其他服務共用免費額度，需觀察實際用量，必要時以 Cloudflare 邊緣規則限制請求。
- 不呼叫付費模型，不增加 Token，不引入 KV、Queue、Durable Objects 或第三方分析服務。應用資料不保存網路身份，但雲端基礎設施日誌需另依實際帳號設定確認。

## 部署與管理

沿用現有 D1 binding（`DB` 或 `資料庫`），首次有效回報／管理員讀取時只建立兩張 `usage_signal_*` 表，不修改帳務表。Worker 模組已加入部署 manifest，合併後走既有 guarded Worker 部署。前端先部署而 Worker 尚未更新時，回報失敗直接捨棄，遊玩照常。

管理員頁「遊玩使用訊號」按需讀取 `GET /admin/usage-signals`，沿用 ADMIN_TOKEN 驗證；不自動輪詢。返回近 30 日的日彙總與每日批次上限。設定 Worker 變數 `USAGE_SIGNALS_DISABLED=true` 可停用接收，管理員仍可查看現有報表。此開關不代表阻擋網路請求。

若需立即刪除歷史資料，可由管理員對 `usage_signal_receipts` 與 `usage_signal_days` 執行 DELETE；不影響帳號／錢包／作品。此 PR 不操作正式 D1、不產生真實玩家資料，也不代表已核對帳號現有免費額度。
