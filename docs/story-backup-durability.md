# 故事庫寫入與完整備份的失敗處理

## 寫入目的地

queuePersist 在接受操作時複製 payload，並固定 storyId / chapterId 等 refs。
persist 優先使用 payload 攜帶的位置，不以稍後的目前故事位置重新解讀。
因此玩家切換故事、還原章節或完整匯入暫時變更 refs 時，先前排入的
寫入仍落在原故事，且不會把目前位置切換回去。未附 refs 的直接 persist
保留原本以目前位置判定的相容行為。

## 寫入結果與匯出

章節的排程寫入失敗會記錄在故事／章節對應表，不會因另一章節成功而
消失。相同章節完整重試成功，或明確刪除對應章節／故事後才移除失敗。

flush() 仍回報資料庫是否可用，讓玩家可以瀏覽已保存的故事；
flush(storyId) 額外要求該故事所有排入章節均已成功提交。完整備份與
建立分支使用後者。最新章節未能寫入時，完整備份會停止，不下載以
舊資料重建的檔案，也不顯示完整備份成功。玩家仍保有目前記憶體中的
故事，可以保持分頁並重試；其他已成功儲存的故事可獨立匯出。

## 交易與分支失敗

Story Library 交易 action 同步拋錯時，主動 abort 整筆交易，撤銷先前
排入的刪除或新增，並保留原始錯誤。建立分支若持久化失敗或回傳 false，
不回報成功，並在目前位置仍指向該新分支時恢復原章節 refs；若期間
已切換到別的故事，就不覆蓋新的位置。建立分支前也再次確認來源位置
沒有在等待寫入期間被切換。

## 驗證與範圍

story-library-durability-core 使用共用交易排程模型，覆蓋交易回滾、
等待佇列時切換故事、直接寫入指定章節、分章節失敗追蹤、停止過期匯出、
重試成功，以及分支 false／throw 失敗後恢復位置。瀏覽器備份測試另用
實際 IndexedDB 驗證同一流程；既有完整故事匯入、分支、歷史檢查點及
作者設定／API Key 不外洩回歸繼續執行。

本輪處理故事庫寫入目的地及完整備份就緒條件，沒有更動故事備份格式。
故事庫多分頁寫入協調，以及匯出期間跨分頁改寫造成的一致性檢查，
仍需後續檢查。


## 核心還原的故障復原（2026-10-18）

Storage.restoreStory 先驗證並準備角色、對話、設定與世界狀態的候選副本，
角色庫也先建立候選清單，不直接修改原有角色物件。準備完成後才切換
App / Chat / GameState，套用偏好與人物狀態／世界模組初始化。

套用偏好前先取得原始 localStorage 字串及 runtime setter 對應的舊值。
三個偏好 key 都寫入後，才呼叫會改動 UI 或記憶體的 setter。任何步驟
拋錯時回傳 false，恢復原角色庫、目前角色、設定、對話與世界狀態的
物件參照，並保留原本不存在的欄位。已改動的 runtime 偏好透過 setter
復原，最後再恢復原始 key 字串／不存在狀態，避免 setter 正規化改寫原值。

記憶欄 setter 的撤銷先在即將捨棄的候選故事上執行，再恢復原故事，
讓延遲儲存仍綁定被捨棄的候選，不會替原故事排入錯誤的自動存檔。
錯誤存於 status().lastRestoreError；完整成功的重試會清除此欄位。
如果復原本身也拋錯，仍逐項嘗試其他項目，彙整錯誤並回報未完整復原，
不會回傳成功。

story-restore-recovery-core 覆蓋正規化、訊息準備、偏好讀取／寫入、
player／narrative／memory setter、人物狀態／世界模組、復原時再次拋錯、
成功還原及重試。瀏覽器測試另使用實際偏好模組、localStorage quota
注入與世界模組例外，確認原故事、runtime 偏好、原始 key 及延遲儲存行為。

範圍：這是核心還原及其直接呼叫 hook 的復原。外層 restoreStory 包裝器
在核心成功後才執行的效果、不受控外掛的網路／檔案副作用，以及瀏覽器
拒絕所有復原寫入時的完整持久化，不能由這個同步流程保證回滾。

玩家偏好的回滾使用執行中快照專用復原，保留尚未持久化的預覽模式；一般存檔匯入仍停用預覽模式並正規化偏好。

## 多分頁的故事庫交易（2026-10-18）

persist 與故事改名、置頂、最近開啟時間、章節改名，現在都在同一筆
readwrite 交易內讀取目前資料並排入修改。IndexedDB 在不同連線間
序列化這些交易，避免舊讀取結果蓋掉另一分頁剛提交的名稱或置頂。
內容存檔保留資料庫中的章節名稱、分支關係及最近開啟時間；分支因
刪除父章節而升為獨立線後，不會被舊 payload 的 refs 接回已刪除父章節。

章節訊息與已失效的檢查點，也在該交易內按最新記錄刪除再完整替換，
不會因先前交易增加較長對話而留下未刪除的尾段。交易回呼拋錯時整筆
abort，保留先前提交版本。新增共用交易排程測試及雙分頁實際 IndexedDB
測試，並確認重新載入後的資料。

範圍：同章節內容仍由最後提交的完整存檔取代，不是對話合併或版本衝突
提示。分頁目前位置仍沿用既有 refs 機制；跨分頁刪除與寫入協調、以及
匯出期間的一致性檢查仍需另行處理。

## 刪除與舊寫入的協調（2026-10-18）

故事、單章節與分支樹刪除，改在同一筆 readwrite 交易中讀取最新記錄、
計算受影響章節、刪除內容、提升存活子分支並更新故事的目前章節。
整個故事沿用 deletion 記錄，章節與分支子樹增加 chapter-deletion 記錄。
刪除與標記同筆提交，失敗時整筆回滾。刪除分支樹也拒絕包含本分頁
目前章節的操作。

persist 在同一交易檢查目標故事、章節及有效父章節的刪除標記。先提交的
寫入會被後續刪除完整移除；先提交刪除後，同 ID 的舊存檔與排隊寫入
會以 YORUBAY_LIBRARY_DELETED 拒絕，不讓已刪除內容復活，也不能在
已刪除的分支起點下建立新分支。已升為獨立線的存活子分支仍可存檔。
佇列記錄失敗並阻止完整備份宣稱最新內容已提交，首次衝突顯示提示，
重複自動存檔不重複提示。完整故事匯入原本就會分配新 ID，不受舊標記阻擋。

刪除標記持續保留以防止長期閒置分頁寫回，尚未加入標記清理策略。
此處保護既有 ID；目前位置沿用既有共用 refs。新 ID 的另存或匯入仍可
建立故事，分頁位置隔離、同章節版本衝突及跨分頁匯出一致性另行處理。

## 開啟中分頁的位置隔離（2026-10-18）

故事庫的目前位置在腳本載入時，從舊 localStorage keys 建立一次分頁內
快照。之後 refs、故事／章節／分支切換、還原與清除都以本分頁記憶體
為準。仍寫回舊 keys 作相容用途，但其他分頁改寫或刪除它們，不會把
本頁的 buildStoryPayload、存檔或分支建立導向另一故事。

本頁仍保留被另一分頁刪除的原 ID，後續寫入會被既有刪除標記拒絕，
不會因共用 keys 被清除而靜默分配新 ID。localStorage 無法讀寫時，
記憶體位置仍可維持，IndexedDB 故事庫可繼續使用。也保留分支位置 0，
不再將第一則訊息的序號當作空值。

重新載入或開啟新分頁仍沿用目前實際載入的共用自動存檔，若 payload
帶有 _library 就以它覆寫啟動快照。這次沒有加入逐分頁的持久化自動存檔
或還原上次各分頁的獨立進度；同章節內容版本衝突及匯出一致性仍另行處理。

## 完整匯出的固定快照（2026-10-18）

完整備份在既有本分頁 save / scoped flush 成功後，只呼叫一次 allRecords，
以該次 IndexedDB getAll 取得的獨立副本，重建全部章節、對話、狀態、
分支關係與檢查點。reconstruct 可接受這份 records，不再逐章重新讀資料庫。
匯出開始時也固定本頁的目前章節偏好，且只選擇快照內實際存在的章節；
若偏好已失效，依故事記錄或第一章回退。

因此匯出讀取後，其他分頁存檔、改名、刪除章節甚至整個故事，都不會
讓檔案混用新對話與舊檢查點，或因稍後刪除而缺少一半章節。輸出代表
那次讀取時已提交的完整版本，不包含其後的變更，也不保證包含另一分頁
尚未提交的記憶體進度。若快照本身已缺少必要故事、章節或 snapshot，
仍明確拒絕匯出。

共用交易排程回歸測試覆蓋讀取後的跨頁存檔、整個故事刪除、本頁切換、
失效目前章節、缺少 snapshot，以及秘密／作者設定不外洩。雙分頁瀏覽器
測試則在實際 IndexedDB 讀取後暫停匯出，由另一頁提交新內容並刪除分支，
確認備份仍保留同一個完整舊版本且可通過匯入格式檢查。
