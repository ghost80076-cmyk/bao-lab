# 本地儲存完整性

## 正常 IndexedDB 寫入

故事以 IndexedDB 為主，自動存檔與手動槽位使用各自的 record。
槽位寫入只修改本次指定的 ID，不以分頁的整份舊快取重寫其他槽位。
同一筆 readwrite 交易再依 savedAt 保留最新 20 槽，避免跨分頁容量
判定互相覆蓋。交易 action 或 request callback 拋錯時會 abort，
回滾先前已排入的修改，並保留原始錯誤。

啟動時先載入完整快取，再同步套回全部待寫操作後逐筆持久化；
初始化期間的新操作加入同一佇列，避免舊重播蓋掉新內容。
任一筆失敗時，記憶體仍保留全部已接受的操作，供備援或匯出。

## 本地備援：單一快照與跨分頁鎖（2026-10-18）

新版備援使用 `bao-lab:story-fallback-snapshot-v1` 單一 key，內容包括
schema/version、自動存檔、槽位、來源版本及快照寫入者資訊。整份 JSON
以一次 setItem 提交；額度不足時不會留下自動存檔已更新、槽位未更新
的半份備援，也不會先刪除上一份完整快照。

瀏覽器提供 Web Locks 時，Storage 使用同一個 exclusive lock 協調：

- 一般 IndexedDB 寫入及寫入失敗後的備援切換。
- 初始化遷移、待寫操作重播與舊備援清理。
- localStorage 備援的讀取、套用操作與提交。

取得鎖後先讀最新共享快照，只套用本次新增、刪除或自動存檔操作；
不拿分頁自己的過期清單覆蓋其他分頁。公開存檔方法仍先更新記憶體，
`flush()` 等待持久化佇列。儲存成功提示也改為驗證新版快照。
錯誤會釋放鎖；某一分頁寫入失敗不會阻擋其他分頁之後儲存。

只由本分頁寫出的啟動快照，在資料庫載入完成後可以補齊來源版本。
混合過其他分頁或不同來源版本的快照，會維持保守狀態，避免錯把不完整
來源升格為可完整替換資料庫的備援。單純降級快照遇到其他分頁既有備援，
採合併保留；明確的刪除仍透過個別操作套用。

## 來源版本與原子遷移

每筆 Storage readwrite 交易在同一 store 更新 `__story_revision__`
內部紀錄（kind=storage-meta）。分頁載入時記住來源版本，此後只累計
自身成功提交次數，不以最新共享版本追平，才能辨識中間插入的遠端提交。
內部紀錄不會列入手動槽位或故事備份。

遷移在同一筆交易中讀取資料庫、比對備援來源版本、決定合併或替換，
並寫回結果。版本相符才允許完整快照同步刪除；版本不同或未知時，以
較新自動存檔與槽位 ID 保守合併。因此衝突時可能保留本來想刪除的槽位。
沒有待遷移資料時不重寫資料庫。清理前也比對備援內容，保留期間已改變
的資料；新版分頁的相關操作另受上述共用鎖保護。

舊自動存檔／槽位 key 以及 yes、complete-v2、complete-v3 標記仍可讀取。
yes 與 v2 缺少來源版本，採保守合併；v3 必須有相符版本才能完整替換。
新版原子快照存在時優先使用它；成功遷移後清理新舊備援。無效的新快照
會原樣保留並回報錯誤，避免以空白資料覆寫可供復原的內容。

故事備份格式、IndexedDB store/schema version 維持不變。

## 驗證與限制

Core CI 包含一般 IndexedDB、初始化重播、備援完整性、槽位多分頁、
遷移版本衝突及備援多分頁測試。覆蓋舊格式遷移、未知來源、正常刪除、
兩分頁新增與刪除、容量限制、quota 回滾、損壞快照保留、鎖釋放及混合
來源不能恢復完整替換權。瀏覽器測試使用實際 IndexedDB、localStorage
和 Web Locks，另驗證重新載入與成功提示讀取新版備援。

沒有 Web Locks 時仍使用單 key 原子提交與本分頁佇列，但不保證不同
分頁的讀改寫互斥。已開啟的舊版分頁也不參與新協定，部署後需重新載入。
分頁清單尚不會即時刷新；相同槽位 ID 及共用自動存檔以最後提交為準。
localStorage 容量仍有限，持久化失敗時應保留分頁並匯出故事備份。
