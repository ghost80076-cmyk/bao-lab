# 從第 1 輪完整重建故事記憶

這是與「重試自動摘要」「AI 整理筆記」「Context Pack」「狀態待補掃描」分離的 **人工救援工具**。

## 使用

從故事的 **記憶工作台 → 記憶總覽 → 完整故事重建** 開啟。

- 預設保留最近 20 輪原文，也可選 10、40 輪。
- 只有真正已完成的玩家／故事輪次可作為來源。開場白連同第一輪一起整理；未完成的最後玩家輸入不納入壓縮。中途缺少角色回覆的玩家輪次會直接拒絕，不偷偷跳過。
- 從第一輪開始，每批最多 20 輪，並依模型實際輸入預算縮小；單輪原文如果過大，停止並提示改用更大容量模型，**不裁切半輪**。
- 每次手動執行最多 4 次付費模型請求。每批完成且核對 JSON 格式、來源 message ID、輪數、供應商完成狀態後，才保存掃描進度。
- 一個或多個原文批次只建立有來源的獨立摘錄。完成擷取後，以階層式合併產生正式摘要候選；獨立的原文證據與人物／世界變化證據保留在重建草稿，避免最終摘要的反覆壓縮抹掉來源。
- 完成後由玩家對照目前正式摘要與新候選稿，再按「確認套用新摘要」。**掃描與合併過程完全不改正式摘要。**
- 套用時只更新 Chat.summary、Chat.summarizedUntil、既有鏡像 memory 和 memoryHealth；保存套用前摘要與游標供回滾。正常故事近期原文、原始歷史、必記事項、Canon、Context Pack、世界狀態、玩家手動欄位與人物知情索引仍保留。
- 人物／金錢／物品的狀態證據是 **人工核對草稿**，不是一鍵覆寫世界狀態。原始對話不能完整證實的細節不能自動歸零或推算。後續狀態修復仍請使用人物／世界狀態工具。
- 套用後若後續自動摘要已更新正式摘要或游標，禁止使用過時備份一鍵回滾，以免抹掉新進度；此時應用完整故事存檔備份還原。

## 風險與安全界線

1. 會產生額外 API/燈火費用。只有玩家明確確認才發起每組最多四次請求，不會背景自動重試。
2. 使用共用 MemoryCore 模型選擇、預算與完成狀態檢查；Gemini 的 PROHIBITED_CONTENT、SAFETY、MAX_TOKENS 等錯誤會停止，保留之前的成功進度，不會切換供應商或繞過其安全限制。
3. 寫入 checkpoint 前先檢查來源輪次指紋、故事所有權與模型配置；來源被編輯時停止，不會錯位續作。允許 **追加** 比凍結來源更新的輪次，並維持原本保留區原文。
4. 完成後儲存需通過 Storage.flush 與持久化驗證（若提供）；未能確認保存時復原目前記憶及候選工作指標，提示備份。
5. 事實性仍依賴模型，不能宣稱無損或完全正確。四類摘要有條目上限，來源證據保留供核對，不應當成會自動重建 Canon 或完整事件知情索引的工具。
6. 原始對話或來源 IDs 若已消失，就不能無中生有地重建，應先嘗試匯入過去的本機備份。

## 開發驗收

- 100 輪歷史 → 保留末 20 輪 → 從第 1 輪連續整理前 80 輪。
- 第 2 批被供應商阻擋，第一批仍保留且可以重開續作。
- 最終摘要完成前，正式摘要、進度、世界狀態及手動筆記完全不變。
- 有效完整草稿才能提交；已追加新回合不影響已凍結的原始來源；修改過去原文必須阻止套用。
- 成功後可回滾，但後續摘要更新過時不可回滾；儲存失敗時不能推進。
