# 懸疑案件：預先固定真相，按揭露條件召回

## 目標
讓夜灣的懸疑、推理、陰謀與群像作品，可以在故事開始前把**既定客觀真相**當成一份固定的本機資料，而不是讓每輪 AI 隨機改寫犯人、原因或結局。採用既有私人世界書 `worldbookLibrary.installed` 與 `worldbookFlags`，沒有第二套世界狀態資料庫、導演服務或額外模型呼叫。

## 作者／玩家操作
1. 進入故事 →「世界書」→「建立懸疑案件 · 預先固定真相」。
2. 填入案件名稱、核心真相；可選填玩家開局確定已知內容、待揭露線索（每行一條）。
3. 點「固定案件真相」，確認後儲存為**這份故事的私人世界書**；預設不啟用，故事不會突然改變。建立入口不提供任意修改已提交答案；若確實要重寫，必須移除舊案件並明確重建。
4. 在世界書啟用該案件；開局已知內容可隨原有世界書召回，**核心真相、待揭露線索都受 requires flag 控制**，在明確勾選「已得知資訊」前不進入任何世界書背景資料。
5. 故事確實揭露某條線索時，由玩家自行勾選「玩家已取得線索 N」；等真相**已經公開**，再勾選「真相已公開（解除模型保密鎖）」，並再次確認。揭露條件可取消，已經送給模型的訊息無法收回。

## 資訊隔離與限制
- **未公開真相不進 Prompt**，不是在 Prompt 裡叫模型保密。內容只保存在本機故事的私有 JSON，也會隨玩家的故事備份移動；它對可以取得備份檔或本機儲存的人並非密文。已建立的答案不由回合摘要或 AI 導演改寫。
- **不保證自動推理或完美前後一致**：未揭露前模型本來就不知道封存的答案，不能憑空安排與真相完全一致的伏筆；線索出場、已知範圍和揭露時機由創作者與玩家管理。將來若要模型在完全不揭曉答案的情況下安排真相導向的伏筆，需要更細的 actor-scoped 導演契約及另外的實聊驗證，本階段刻意不加。
- 真相解除封鎖後會進入既有模型上下文，用來維持已公開的案件事實；**這不會自動授予任何 NPC 歷史知情權**，但現有通用模型仍可能將敘事背景與 NPC 認知混淆。世界書角色知情限制及 NPC 設定需照常遵守。
- 原有 Canon、聊天歷史、角色卡及其他世界書中**已寫出的秘密**不會被這份案件檔案自動遮蔽。若相同秘密本來就在其他 Prompt 來源裡，單靠此鎖無法保證全站無劇透。
- 案件僅新增可選私人 pack，不修改 `App.buildMessages` 的基本組裝；未啟用時不增加輸入 Token，不改變 stable prefix。開局已知資料與解除封鎖後的線索會佔用既有動態召回 Token 預算（每輪有限量召回），不新增付費模型請求。

## 技術
- `YoruWorldbookLibraryCore.createMysteryCase` 將作者輸入轉換成原生 private pack（schema version 1），採用無劇透標題與條件旗標。秘密條目使用 `mode="foundation"`、`requires: ["mystery-...-truth-public"]`；逐條線索使用同樣的條件式 gate；開局資料無 gate。
- 原有 `core.select` 先處理 requires，再計算命中與預算；無 flag 時，即使查詢猜到案件真相，也不會載入被封存的條目。現有 `worldbookFlags` 保留於故事狀態，不儲存在別的獨立資料表。
- `worldbook-library.js` 新增可展開作者表單、確定後存入本故事（未自動啟用）、標記條件時使用容易理解的文字；公開真相勾選需確認。
- `tests/worldbook-library-core.cjs` 驗證早期封鎖、逐條開放、揭露前後文字與原生快照；`tests/e2e/mystery-truth-lock.spec.cjs` 驗證 390px/1280px 表單、保存、未開放 Prompt、手動條件與確認交互。與現有世界書回歸一起在 CI 檢查。

## 後續選配
真相鎖定與玩家劇情期待是不同用途：前者是創作者已確立的客觀秘密，後者只是玩家希望探索的方向；不要互相當成事實。下一個改善方向是 Creator 的「人格四軸」（成因、外顯行為、失控條件、代價），不把長文規則每輪硬塞進 Prompt。
