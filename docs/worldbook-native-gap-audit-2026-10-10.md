# 世界書機制與夜灣原生能力比對（2026-10-10）

## 結論

玩家提供的世界書條目主要反映六類需求。夜灣已具備模組化世界資料、人物名冊、在場狀態、結構化時間軸、事件排程、Context Pack 與動態提示；不應把相同 OOC 規則再複製進每張作品。

本輪只補目前確定缺少、而且適合由資料層保證的「NPC 身分與外貌連續性」。AI 導演仍依 `docs/ai-director-experiment.md` 維持實驗狀態，未繞過其品質門檻進入正式流程。

## 比對

| 玩家世界書需求 | 夜灣現況 | 決定 |
| --- | --- | --- |
| 條目可獨立啟用、停用、調整追蹤頻率 | `world_modules`、世界模組管理器、MOD 包已支援 | 沿用，不重做 |
| 課表、期限、約定與時間推進 | `world_clock` 已提供相對時間、排程、到期、完成與取消 | 沿用；作品課表可使用世界模組保存資料，明確期限交由世界時鐘 |
| 玩家控制權、資訊隔離、NPC 自主 | 平台規則與角色 Prompt 管線已統一處理 | 不複製到作品世界書，避免規則重複與衝突 |
| 記憶與劇情連續性 | 智慧記憶、Context Pack、世界狀態、人物狀態已分層 | 沿用；不再新增第二套記憶庫 |
| 劇情節奏、伏筆成熟度、離場 NPC 行動 | 已有 AI 導演設計文件，但仍標示 experiment only | 暫不正式啟用；先完成代表性作品評測 |
| NPC 首次登場、別名、固定外貌、換裝 | 原名冊只有姓名、身分、情緒、地點、關係與 presence | 本 PR 原生化 |

## 本 PR 的資料契約

- `npc_id`：夜灣為每份故事內的人物建立穩定 ID；狀態更新優先用 ID 對應人物，舊存檔則在下次讀取狀態時補齊。
- `aliases`：最多 8 個已確認別名；用別名更新時合併至正式人物，不建立重複 NPC。
- `appearance`：固定外貌錨點。第一次有明確資料時建立；只有故事明確造成長期外貌變化，狀態 PATCH 才能以 `appearance_change: true` 更新。
- `outfit`：當前穿著；只有文本明確換裝時更新。
- `first_seen`：由夜灣在人物首次確認在場時，依當前故事時間、地點與輪次建立；模型不能提交此欄位。
- 所有欄位都隨既有 Local-first 故事狀態、備份、Context Pack 與相關 NPC Prompt 保存，不新增外部服務或額外模型呼叫。

## 非目標

- 不把自然語言的「30% 機率」宣稱為可靠亂數。
- 不增加第二次 AI 導演 API 呼叫。
- 不把固定外貌與當前服裝混成同一欄。
- 不把作品名稱、世界模板或介面標籤建立為 NPC。
