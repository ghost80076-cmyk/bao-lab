# 故事歷程與收藏：第一批

入口：故事總覽 → 故事歷程與收藏。對既有世界狀態 `events` 建立公開展示層，不重做分支、關係數值或 Gameplay UI。

- 不需作者新增設定。世界狀態已記錄的事件自動進入歷程，玩家可搜尋、收藏。
- 只讀 `events` 的字串，不從人物秘密、世界書、私有模組、記憶摘要推斷新事件。這不會把原本私有的設定變成公開資料。
- `state.storyHistory` 是本故事的可選資料；每筆只有 id、text、source、time、location、starred。公開事件內容仍取決於原有狀態整理品質，不代表前端獨立核實劇情。
- 事件在 `GameState.addEvent()`、既有 20 則近期事件截斷之前記錄。最多 500 則；滿額時移除最舊未收藏項，全部收藏時停止新增。不是無限歷史庫。
- 相鄰相同事件合併；非相鄰重複事件可保留。尚無語意分類、成就條件、秘密解鎖或自動判斷「重要回憶」。
- 舊存檔首次閱讀只投影已有的最多 20 則事件，不寫入、不回推時間或地點；新增事件或收藏才將投影存回故事。
- 全部資料沿用既有 GameState 快照、訊息 checkpoint、分支、故事備份和還原。分岔前繼承，之後獨立；改寫或切換回覆沿用原有快照回復。收藏同樣屬於當時的故事快照。
- 沒有新增模型呼叫、提示契約、雲端儲存；不把收藏表加入狀態模型快照。舊作品原本沒有事件追蹤時，不會自行生成歷程。
- UI 使用純文字節點，避免把事件內容當 HTML；收藏寫入前核對目前故事狀態物件，避免舊視窗修改新故事。

## 驗證

`node tests/story-history-core.cjs` 覆蓋舊存檔投影、隱藏欄位排除、容量與收藏保留、狀態更新接入、快照副本隔離與 Prompt 排除。

`tests/e2e/story-history.spec.cjs` 覆蓋 390/1280px 入口、搜尋、收藏、HTML 字面呈現、三主題寬度、實際分支 checkpoint、完整故事備份匯入還原。由 Story controls Chromium CI 執行；核心測試加入 Core CI。

下一批應用既有作品驗證事件品質，再設計可選展示模板與公開來源綁定；不把作者秘密或完整模組內容直接掃進收藏。
