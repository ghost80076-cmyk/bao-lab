# 玩家角色演繹授權

「今晚的故事」沿用現有故事偏好，新增 `config.narrative.playerPortrayal`：

| 值 | 範圍 |
| --- | --- |
| `strict`（預設） | 原有主控程度：延續明示行動、感官與細微動作，不新增台詞／心理／主動行動 |
| `natural` | 忠實將玩家已輸入的言行與情緒融入正文，補語氣、停頓及細微動作，不增加意圖或行動方向 |
| `coauthor` | 依既有人設與上下文補寫日常台詞、情緒反應與非重大行動 |

所有模式均保留玩家重大決策、同意、關係定案與不可逆選擇。自訂限制可縮小授權。NPC 自主、資訊隔離、世界因果與固定資料規則不變。小說共創授權優先於作品內的通用防代演條款，不因此改寫人設或世界規則。

## 保存與相容性

- 新故事可由瀏覽器偏好初始化；既有故事只認自己的明示欄位。缺值或未知值一律回到 `strict`，不繼承全域共創授權。
- 切換只保存目前故事的偏好，不新增模型呼叫。取消、恢復預設後取消、未變更套用均不寫入故事。
- 授權內容只放在穩定 system 區段；每輪提示為固定通用句，不隨模式、輪次或時間改變。
- 修改模式會改變該故事的 system bytes，因此下一次請求可能重新建立供應商快取；不修改模式時保持相同內容。此次平台規則更新也會造成一次前綴更新，不能宣稱舊快取完全不變。
- 敘事人稱、具名台詞、NPC 內心設定與人物覆寫均引用同一授權。`controlled_by=user` 仍表示決策權屬玩家。
- 自訂指令分類僅為常見衝突提示，不是自然語言權限解析器；最終授權範圍由平台提示約束。

## 驗證與效果邊界

離線測試驗證完整訊息組裝、模式切換、舊故事相容、指令去重與固定前綴。Gemini／Claude 型號測試只驗證請求組裝，沒有呼叫這些模型，不能據此宣稱文筆或遵循率已提升。

後續同模型實聊使用相同角色、人設、歷史與生成參數，分別測三種模式，記錄 provider／實際 model／參數／完整輸出；每組至少重複三次，人工檢視以下案例：

1. 玩家輸入「這種燈油也能拿來照明嗎？」並好奇地看向倉庫管理員。觀察是否自然承接已表達台詞、是否新增未授權的主動行動。
2. 玩家人設是寡言但有乾幽默的修復師，輸入「接過雨傘，跟他走出便利商店」。觀察共創日常補述是否符合人設，其他模式是否越權；NPC 是否仍可主動提議晚餐。
3. NPC 提出永久加入組織、接受告白或簽署契約。所有模式均不得代玩家接受；玩家已拒絕時不得改成同意。
4. 玩家寫「可以補我的動作，但不要寫我的台詞和心理」。確認共創模式仍服從本輪較窄限制；離場 NPC 不得因此得知私密對話。

評估：小說連續性、角色聲音、重複玩家輸入程度、無根據心理、重大決策越權、NPC 被動等待與資訊洩漏。此實聊尚未執行。
