              進階：直接編輯 JSON（懂格式再用）

              JSON 格式參考

              contacts 是聯絡人、threads 是聊天室、photos 是相簿、notes 是備忘錄；apps 決定桌面顯示哪些 App。

              {"contacts":[{"id":"friend","name":"好友"}],"threads":[{"id":"friends","name":"朋友群","participants":["friend"],"messages":[{"from":"them","senderId":"friend","text":"晚點見。"}]}],"photos":[],"notes":[{"id":"memo","title":"待辦","text":"下班買牛奶。"}],"apps":["kakao","photos","notes"]}
              進階機關格式參考

              只有超出上方「故事機關」表單能力時才需要直接修改。密碼是劇情機關，請勿填真實帳號密碼。

              {"interactions":{"version":1,"locks":[{"target":{"app":"kakao","id":"friends"},"code":"0427","hint":"四位數故事密碼"}],"events":[{"id":"read-memo","when":{"action":"read","target":{"app":"notes","id":"memo"}},"unlock":[{"app":"kakao","id":"friends"}],"notification":"聊天室已解鎖"}]}}

              角色頭像對話

              用於故事正文：以發話者的頭像呈現對話，不需要開啟手機玩法，也不會自動與手機聯絡人頭像同步。選「角色頭像對話」並填入發話者姓名及圖片。單角色卡填主角色姓名；世界卡可加入固定 NPC。每位人物一張頭像，最多 12 位。玩家可另外設圖，不需要替舊作品補圖。

              進階設定：主要角色、世界、作者備註
              NPC 人格四軸 · 成因／行為／失控／代價（選填）

              幫作者整理真正影響角色行動的四個因素；不替你生成個性，也不修改平台的 NPC 自主權或資訊隔離。只有按「加入角色卡」才會寫入，下次儲存草稿／匯出時跟原有設定一起保存。

              這是選填工具，不會自行改變角色卡設定。

              

              範例：【世界書：魔法學院｜魔法學院,學院】，下一行寫學院資料，最後以 【/世界書】 結尾。每輪最多載入 3 條相關資料；長內容仍會佔用 Token。若要寫故事的第一幕，請使用上方「初始訊息」。
              以下兩欄都是補充這張作品的特殊需求，不必重寫網站內建的 NPC 自主、資訊限制及基本敘事規則。核心設定已有相同內容時，留白即可；填寫的內容預設會隨每輪對話送給 AI，重複文字會增加 Token。
              

              新功能放哪裡？作者設定與玩家選擇

              作品欄位會隨草稿、角色庫及匯出保存；玩家故事偏好由玩家另外設定，不會因匯入角色卡而授權 AI 代演。
              

                

              • 作品：手機介面、角色頭像、NPC 人格四軸、互動 UI，使用本頁對應欄位。
                • 

              • 玩家：「今晚的故事」設定演繹授權、單輪觀賞、場景投入、劇情期待與自訂長期指令；故事回覆語言在故事設定中選擇。
                • 

              • 快捷指令：在故事內管理及匯入／匯出 JSON；與每輪生效的長期指令分開。
                • 

              • 懸疑案件：故事內「世界書 → 建立懸疑案件」固定真相、手動揭露線索；不要把封存答案同時貼進核心設定。
                • 

              • 舊故事狀態卡住：使用故事中的狀態重建；無須為此重寫角色卡。
                • 

              

              Creator MCP 可產生手機資料與原生作品包。文風建議只供參考；作品敘事要求請填作者專屬敘事偏好，玩家演繹授權由玩家選擇。
              

              

              進階設定：互動 UI 外觀

              Gameplay UI 使用平台原生元件；作者可以選主題、主色、密度、圓角與數值條風格，不會執行任意 CSS／JavaScript。只有角色卡已經包含 Gameplay UI schema 時才會套用。
              

              






              


              建立購買／消耗按鈕
              

              設定一次後，玩家按鈕會直接扣款、增減背包並存入故事，不需要 AI 計算。資源或庫存不足時整筆取消。初始資源只在新建欄位時使用；已有資料會保留。
