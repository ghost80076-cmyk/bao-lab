# BAO/LAB 視覺提案｜夜讀書房（兩輪草稿）

保留 BAO/LAB 原有近黑、薰衣草紫與薄荷綠，讓「角色是封面、故事是藏書、聊天是閱讀」成為共通的視覺語言；不照搬其他網站的配色與版型。

## 第一輪｜閱讀節奏

`css/bao-editorial.css` 統一首頁、作品探索、人物詳情與故事書庫的字級、封面和留白；`css/bao-editorial-polish.css` 修正截圖看到的標題斷字，`js/bao-gallery-focus.js` 把匯入與管理按鈕放進可展開的原生 `<details>`，保留同一批按鈕與事件。既有故事、API 金鑰與作者 HTML 都沒有更動。

## 第二輪｜獨立審美回饋後的具體取捨

- **採納：** 弱化書庫和首頁的「卡片包卡片」；作品卡由第一版的 3:4 改為 2:3 海報（CSS 顯示裁切，不改原圖檔），人物圖作為整張卡的主角；主標題改用裝置本機的明體／襯線 fallback；手機詳情首圖降低高度、資訊接在下方；作品與詳情頁隱藏斗內浮動鈕，包包助手保留可點擊的 46px 圖示與既有面板。
- **不採納：** 全站高飽和紫綠漸層 CTA、只有 40% 白色不透明度的 12px 提示、未有素材的全螢幕圖片輪播，以及未經導覽驗證便把手機入口全部塞入漢堡選單。這些方案不一定改善閱讀，也可能傷害辨識度、可及性及既有操作。
- **事實校正：** PR #40 第一版的探索封面已是 **3:4**，並非評審文所說的 1:1／4:3；實際斗內與包包控制使用 `.bao-support-float`、`.bao-mascot-launch`，不是 `#feed-bao`／`#find-bao`。品牌主按鈕用的是 `#9c8cff` 一系，不是評審文推測的 `#7B61FF`。第二輪以實際 selector 和程式碼為準。

## 技術邊界、驗收與撤回

第二版的外觀集中於 `css/bao-editorial-cinema.css`，由已存在的展示載入器接在兩層 editorial CSS 之後；回退僅需刪除對應 stylesheet 載入及其 CSS。設計不接觸遊戲記憶、存檔、API、聊天滾動、作者 HTML，亦不改變角色／故事原圖資料。原生導覽、匯入、建立故事、讀取進度與刪除操作的可用性，由 390px、1280px 的 Chromium 截圖及 Playwright smoke 驗證。真人行動裝置手動驗收和較完整的跨瀏覽器測試仍需完成，PR 維持草稿，未合併／未部署。

**本次仍非全站統一終稿。** 聊天內的關係／狀態人物面板、章節編輯介面與完整導航資訊架構，留待下一階段以真實畫面及使用任務確認。

## Core UI 定案｜A 夜幕典藏

使用者已選定 **A｜夜幕典藏（Cinematic Night）** 作為 Core UI 主軸，並明確指定兩個融合點：

- **A 為主體：** 首頁黑紫漸變舞台、大字海報式標題、角色卡 2:3 海報比例、人物詳情維持電影作品頁的構圖。分類入口降為安靜的電影類型篩選，不再使用大型功能卡。
- **B 只借 Tag：** 角色卡與詳情標籤採半透明膠囊、細邊框及 `backdrop-filter: blur(12px)`，資訊保持可讀但不搶立繪。
- **包包保留陪伴感：** 首頁、角色探索與人物詳情使用 46–50px 的圓形懸浮入口，隱藏長文字標籤，僅保留微紫／薄荷綠光暈與非常輕微的呼吸動效；`prefers-reduced-motion` 下關閉動畫。斗內浮動鈕在這些核心視覺頁隱藏，避免雙重懸浮元件遮擋作品。
- **仍不動資料流程：** 上述全為展示層，不改角色檔、故事內容、API Key、IndexedDB、作者 HTML 或按鈕原事件。

2026-09-23 的 Chromium 視覺 smoke 以 390px／1280px 驗證首頁、角色探索、人物詳情與故事書庫；另包含既有開始故事／書庫繼續故事操作。首次 A 版因 Hero 光暈造成 13px 水平 overflow 被測試抓到，之後改為 `overflow: clip`，最新視覺工作流通過。
